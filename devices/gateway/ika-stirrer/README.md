# 设备模块：IKA 磁力加热搅拌器（NAMUR 串口）

一个工位上的几块 IKA 磁力加热搅拌器（RCT digital、C-MAG HS 7 control、RET control-visc……）经 NAMUR 串口命令接进 ILCS：
网关跑在接加热板的那台电脑上，每块板一条串口（或串口服务器），ILCS 侧用 `http_json_v1` 接入，能力 `cap.ely.stir`。
一个位置一块板、放一瓶。去重、台账、查询、令牌、TLS 由 `ilcs_gateway` 负责；计时、停止确认、部分启动回退在本模块。

| 文件 | 内容 |
|---|---|
| `driver/link.py` | 文本链路（TCP 串口服务器 / 本机串口，pyserial 用到时才导入）：读命令一问一答，写命令只发不读；断线丢掉连接、下次重连，发之前清掉晚到的旧字节 |
| `driver/namur.py` | 一块板的 NAMUR 命令：读温度 / 转速 / 设定值（核对应答里的通道号），写设定值，开关加热 / 搅拌，看门狗模式 2 |
| `driver/device.py` | 映射成 `ilcs_gateway.Device`：一瓶一个位置、参数核对（不能制冷）、计时线程、停止确认、部分启动回退、作业记录、重启不续时 |
| `driver/config.py` | 网关配置（`--config`）：位置（链路、温度与转速极限、温度探头）、室温、程序、看门狗 |
| `simulator/namur_server.py` | 假加热板：TCP 上说 NAMUR（写命令不回），一阶温度模型、转速爬升、设定值压到量程里、看门狗模式 2；可单独起 |
| `simulator/__init__.py` | 模拟工位：每个位置起一块假板，真实接口照常连它们；故障注入在设备层（`FaultState`） |
| `simulator/stirrer-sim.json` | 容器里跑模拟网关用的配置（4 个位置，ILCS 必须指定位置） |
| `gateway.py` | 入口：`--simulate` 用假板；`--check` 只读地问一遍每块板 |
| `profile.json` | ILCS 设备接入模板文件（草稿），导入后核对、由另一个人发布 |
| `tests/` | `test_module.py` 对假板跑 ILCS 接入验收清单（含故障项目）与驱动规则（含多瓶、部分启动、失联、重启）；`test_namur.py` 真实接口对着假板走 TCP |
| `deploy/README.md` | 在接加热板的电脑上运行：接线、固定 COM 号、注册服务、停服务 / 重启时板子怎样、第一次动作级验收 |
| `deploy/Dockerfile`、`deploy/compose.yml` | 在 ILCS 那台机器上起模拟网关（4 块假板），接进 ILCS 的后端网络，给联调与模拟实验用 |

```bash
api/.venv/bin/pytest devices/gateway/ika-stirrer/tests                              # 自测（不要 pyserial、不要 ILCS 数据库）
python devices/gateway/ika-stirrer/gateway.py --simulate --insecure --port 8443      # 本机联调（4 块假板，自动挑位置）
python devices/gateway/ika-stirrer/simulator/namur_server.py --port 4001             # 起一块假板给真实接口连（link 写 tcp 127.0.0.1:4001）
python devices/gateway/ika-stirrer/gateway.py --config stirrer.json --check          # 现场接好线：只读地问一遍每块板
```

## NAMUR 命令（这里用到的）

9600 波特、7 数据位、偶校验、1 停止位（7E1），无流控；命令大写、CR LF 结尾，应答 CR LF 结尾；设备从不主动发数据。

| 命令 | 应答 | 用途 |
|---|---|---|
| `IN_NAME` | `RCT digital` | 身份、健康检查 |
| `IN_PV_1` / `IN_PV_2` / `IN_PV_4` | `25.3 1` / `80.1 2` / `300 4`（数值 + 通道号） | 外置探头温度 / 加热盘温度 / 实际转速 |
| `IN_SP_1` / `IN_SP_4` | 同上 | 温度 / 转速设定值（回读核对） |
| `OUT_SP_1 x`、`OUT_SP_4 x` | **不回** | 写温度 / 转速设定值 |
| `START_1` / `STOP_1`、`START_4` / `STOP_4` | **不回** | 开关加热、开关搅拌 |
| `OUT_SP_12@t`、`OUT_SP_42@n`、`OUT_WD2@m` | 回显 | 看门狗模式 2 的安全温度、安全转速、超时（缺省不用） |

写命令没有应答，写出去不等于设备收到了：网关每次写完紧跟一条读命令，读得到应答才算送到（同一条线、按顺序）。
应答带通道号的都核对，晚到的旧应答不会被当成下一条的。模式 1 看门狗（`OUT_WD1@`）触发后要重新上电，不用。

## 一条 ILCS 指令怎么落到加热板上

- **一条指令 = 一瓶或几瓶，一瓶占一个位置（一块板）。** 参数：`temp`（℃）、`time`（s）、`rpm`、`position`。
  - 一瓶：`position` 写位置的序号（1 起，按配置里的顺序）或位置号本身（`"2"`）；
  - 几瓶：ILCS 的逐孔参数 `wells: {孔位: {temp, time, rpm, position}}`，孔位没写的参数用顶层的值（步骤固定参数是逐孔参数的
    缺省值）；两瓶落到同一个位置就拒绝；要用的位置有一个不空闲，一个都不启动。
  - 程序：ILCS 设备方法的「程序」要登记在 `programs` 里（没带方法的指令用 `default_program`）。加热板没有内置程序，
    温度、时间、转速都由参数给；**带别的参数、带物料一律拒绝**，不悄悄忽略。
- **只能加热，不能制冷**：`temp` 低于室温 `ambient_c` 就拒绝；高于室温才开加热；等于室温只搅拌、不碰温度设定值。
  `rpm` 为 0 只加热、不开搅拌；既不加热也不搅拌拒绝。超过位置的 `max_temp_c` / `max_rpm`、低于 `min_rpm` 拒绝。
- **启动**：每块板先读一次（读得到、搅拌子没在转、外置探头读数像真的）→ 写设定值并回读（板子把它压回量程就拒绝，
  设备没动）→ `START_4`、`START_1` → 再回读设定值（有的型号 `START_1` 后设定值会复位），不对重发一次。
- **计时在网关里**：每次启动起一个计时线程，到 `time` 秒就 `STOP_4`、`STOP_1`（加热开没开都发），读一次确认送到；
  ILCS 一次都不来查也照样停。时长从启动算起，**不等到温**。
- **状态**：每块板的停止都确认了才报完成 / 失败——没确认就一直重试、一直报在跑（错误里写明哪块没确认），不让 ILCS
  以为设备已在安全状态。几瓶时：有一瓶在跑就是在跑，全部停下且都正常才算完成，有一瓶失败就是失败（写明孔位、位置）。
- **明确拒绝 vs 结果未知**：启动命令发出之前出的错（参数不对、位置不空闲、读不到板子、设定值写不进去或回读不对、
  作业记录写不进去）是明确拒绝，板子没动。第一条启动命令就没写出去也是拒绝。
- **部分启动**：已经启动了几块、后面出了错（命令写不出去、启动后回读失败或设定值重发也不对）——**先把这条指令启动了的
  板都停下**，再按结果未知抛出（错误里写明哪几块启动过、停止确认了没有），交人核查；不报「没动」，也不认这个作业。
  停止没确认的位置一直占着、网关一直重试，线通了就停下。不像充放电柜那样留着已启动的通道不管：加热板不能没人计时。
- **失去监视**：运行中某块板 `lost_after_sec`（缺省 30）秒、且至少连续 3 次读不到，提前停下这一瓶、判失败
  （线通了才停得下，之前一直重试）；别的瓶照常到点。短暂的串口抖动不算。
- **终止**：计时线程马上停这条指令还在跑的板，确认之后才回；15 秒内确认不了回结果未知（网关接着重试）。**不做保持**。
- **网关重启不续时**：作业记录在状态目录里，重启后按作业号照样答得上（跑完了的照报完成和实测值）。重启时还没结束的作业，
  先把它的板停下，再判失败（写明计划多久、重启前开始了多久）——网关不在的那段时间板子转没转、温度怎样都不知道。
  启动途中崩掉的，重启后把这条指令的每个位置都停下，不认这个作业（结果未知）。停服务（SIGTERM）时先停板再退出。
- **实测值**：一瓶时回执 `delivered` 是 `{position, sensor, temp, rpm, duration_s}`；几瓶时在 `delivered.wells[孔位]`
  里逐瓶给（失败的瓶多一个 `error`）。`temp`、`rpm` 是停之前最后一次读数，`sensor` 说明温度是瓶里的外置探头
  （`external`）还是加热盘（`plate`）；`duration_s` 是这块板实际从启动到停下的秒数。遥测是 `temp`、`rpm`（几瓶时名字带孔位，
  如 `temp@A1`），`setpoint` 是设定值（不加热时温度没有设定值）。

## ILCS 里怎么建

- **工位**：通道数 = 位置数，**按样本计通道**（`channel_unit: sample`，一瓶占一个位置）；能力 `cap.ely.stir` 的参数
  `temp`（℃）、`time`（s）、`rpm`（rpm）之外**要加** `position`（整数，单位「号」）——C 公司产线的能力字典里现在只有前三个。
  工位极限：`temp` 下限是室温（**EL-D-MIX 现在登记的 −20 ℃ 要改**，否则 ILCS 会排这台板做不了的低温步骤，下发时被拒）、
  上限取各位置 `max_temp_c` 的最小值；`rpm` `[0, max_rpm]`；`position` `[1, 位置数]`。
  制冷搅拌（EL-D-STIR，−20–0 ℃）、冷藏搅拌（EL-D-COLD）这些板做不了，见下文。
- **接入**：导入 `profile.json` 成接入模板、另一个人发布，工位套用模板，连接参数填网关地址、证书、设备编号。
- **设备方法**：程序写 `programs` 的键（如 `STIR-FINAL`），适用型号写板子型号；输出项 `temp`、`rpm`、`duration_s`
  关联指标（指标单位 ℃、rpm、s，和回报单位一致，ILCS 不换算）。回报值按样本写成「设备回报」检测结果、待复核。
- **瓶子放在哪个位置**：搅拌步骤的 `position` 不写固定值，用逐样本前馈——
  - 人工放瓶：先放一个「放瓶」人工步骤，表单里有按样本录入的数值字段「所在位置」，前馈来源单位「号」、预期范围
    `[1, 位置数]`；
  - 机械手 / 上位机放瓶：让放瓶那一步按孔位回报放到的位置（`delivered.wells[孔位].position`），搅拌步骤逐样本前馈取自它。
  这样 ILCS 一条指令带着每瓶的位置（和每瓶自己的温度、时间、转速）发给网关。

## 在 ILCS 那台机器上模拟联调

```bash
# 1. 起模拟网关（4 块假板，容器 ilcs-ika-stirrer-sim，接 ILCS 的后端网络 ilcs_backend）
docker compose -f devices/gateway/ika-stirrer/deploy/compose.yml up -d --build
# 2. deploy/.env 的 ILCS_ADAPTER_ALLOWED_HOSTS 加上 ika-stirrer-sim，重建 api 与 executor（docker compose up -d）
# 3. 导入 profile.json、发布；工位套用模板，base_url https://ika-stirrer-sim:8443/api/v1，设备编号 SIM-IKA-STIR-01
```

模拟网关自报为模拟器：只读级验收就放行；它回报的值在 ILCS 里带「模拟」标记、仪器注明模拟设备，不进闭环训练数据。
正式环境（`ILCS_ENVIRONMENT=production`）拒绝接入模拟器。

## 还没做 / 要现场核对的

- [ ] **制冷**：这些板只能加热。EL-D-STIR（−20–0 ℃）、EL-D-COLD（−20–10 ℃）要带冷却的工位：低温恒温槽 / 冷水机
  （如 IKA 的恒温循环器、Huber、Julabo）另写驱动，或冷却台 + 搅拌器组合；ILCS 的工位极限照实登记。
- [ ] **到温再计时**：现在时长从启动算起。要「到 60 ℃ 后保持 1 小时」，流程里拆成预热 + 搅拌两步，或现场确认判据
  （到温容差、等多久算没到）之后再加。
- [ ] **`STATUS` 命令**：有的型号能读加热 / 搅拌开没开、报错码（`ER x`），各型号不一样，现在没用。停止靠「写完读一次」确认
  送到，看不到板子自己报的故障；板子报错停机网关只能从温度、转速读数上看出来。
- [ ] **没插探头**：`sensor: external` 时，没插 PT1000 读 `IN_PV_1` 会回什么要在真板上看（现在把 −50–400 ℃ 以外的读数当没插）。
- [ ] **看门狗**：`OUT_WD2@m` 有没有回显、要不要在 m 秒内重发同一条（这里每 m/3 秒重发一次）、`OUT_WD2@0` 回什么、
  安全转速能不能是 0，都要在真板上核对后再打开 `watchdog_sec`。触发后板子照开、只是设定值回落，网关重启后照样先停板。
- [ ] 现场核对：停搅拌后 `IN_PV_4` 是不是回 0（「搅拌子在转」的判断靠它，阈值 20 rpm）；设定值回读的容差（温度 1 ℃、
  转速 10 rpm）够不够；命令间隔 50 ms 够不够；有的手册写「空格 CR LF」结尾（链路的 `eol` 可以改）；固件版本读不到（`firmware` 空着）。
- [ ] `profile.json` 是草稿：核对连接参数示例后导入，由另一个人发布。
