# ProtoForge 联调线全流程（多温度矩阵）

用本机的 ProtoForge 模拟设备，在 ILCS 上把一条测试流程从头配到尾：设备接入 → 环境采集 → SOP → 能力与设备方法 →
实验流程 → 多温度矩阵方案 → 实验任务 → 排程 → 批次执行 → 数据复核 → 报告。三台设备都经驱动宿主接入，ILCS 只走 SiLA 2。

> 2026-10-06 起 ProtoForge 里从站 2 的握手 PLC 已删，Modbus 只剩从站 1 的温湿度传感器：ST-PF-MB 改成只读写点位的环境传感器，
> 流程里没有「PLC 控温运行」了（SOP-PF-01 v5、流程「ProtoForge 多温度矩阵控温联调」）。
`scripts/load-protoforge-flow.py` 按本文一次跑完，界面上每一步都能对着看、也能手工照做。

## 设备与分工

两台设备参与温度设定：方案用设计点给每个样本一个温度，两台设备依次为每个样本设定温度。它们一次只能做一个设定，
由驱动宿主里的映射插件**按样本依次执行**：一条指令带全部样本的温度，插件一孔一孔跑完，回执按孔位回报，结果落到各自的样本上。

| 工位 | 设备（ProtoForge） | 接入（驱动宿主） | 在流程里做什么 |
|---|---|---|---|
| ST-PF-MB | Modbus TCP 从站 1 的温湿度传感器 | `PF-MB-PLC`（50201），只读写点位（`"tasks": false`，没有 TaskExecution） | 环境传感器：温度、相对湿度记成「设备模拟联调区」的读数；不承接能力 |
| ST-PF-OPCUA | OPC UA 温控 / 压力节点 | `PF-OPCUA`（50202），点位 + 设定类任务 | 「温控器设定温度」（`cap.tc_setpoint`）：每个样本写 `Temperature` 节点、回读；高报为真判故障。兼作压力传感器 |
| ST-PF-HTTP | HTTP REST 设备 | `PF-HTTP`（50203），点位 + 设定类任务 | 「环境箱设定温度」（`cap.chamber_setpoint`）：每个样本 `POST /temperature`、按点表读回；状态不是 normal 判故障 |

OPC UA、HTTP 两台在 ProtoForge 里没有启动信号，写完设定值就生效，所以按**设定类动作**接：点表映射的启动写
`{"write_only": true}` 并配 `idle_after_start: "done"`；REST 映射的能力请求本身就是写设定值的请求，实测值写成
`{"point": "temperature"}` 按点表读回。写法见驱动宿主插件配置（`ilcs-devices/host/插件配置.md`）「逐孔依次执行」。
驱动宿主的现场配置在 `ilcs-devices/host/sites/local/devices/`（本机在用的是 `data/driver-host/site`），也可以在驱动宿主的设备管理台
（`http://127.0.0.1:50200`）上看状态、改映射、起停各台设备的服务；改了映射照样要在「设备连接」签名批准、重新验收。

前提：驱动宿主在跑、三台设备已经接入并验收（`scripts/load-driver-host-devices.py register`，见 `ilcs-devices/host/README.md`），
ProtoForge 里 Modbus TCP、OPC UA、HTTP REST 三个协议都启动了（Modbus 从站 1 是温湿度传感器，见
`ilcs-devices/simulators/protoforge/README.md`），执行器在跑。

## 一键跑

```bash
python3 scripts/load-protoforge-flow.py register
```

```bash
python3 scripts/load-protoforge-flow.py run --temps 40,60,80 --repeats 1
```

`--temps` 给 2–8 个设计温度（0–100 ℃），`--repeats` 是每个温度的重复次数（1–2）。只走 HTTP、和界面调同一组接口，签名用演示账号
逐次签署；已有的先查后用，重复运行不会多建。每次 `run` 新建一个方案、任务、批次、报告，留在本地库里当测试案例。

### 环境采集配置

实验区的温度、湿度由温湿度传感器给；两台设定设备的温度会被设定步骤改写，不当环境温度。

```json
"environment": {"zone": "设备模拟联调区", "interval_sec": 30, "points": {"temperature": "temperature", "humidity": "humidity"}}
```

这是 ST-PF-MB 的（连接配置里照旧 `"tasks": false`）；ST-PF-OPCUA 的是
`{"zone": "ST-PF-OPCUA", "interval_sec": 30, "points": {"pressure": "pressure"}}`。ST-PF-HTTP 不再兼作湿度传感器，连接配置里
没有 `environment`。写法见 [设备适配器配置模板](设备适配器配置模板.md)「点位读数记成环境读数」。

### 流程的五步

| 步 | 类型 | 内容 | 环境要求 |
|---|---|---|---|
| s01 核对环境与设备在线 | 人工 | 勾选三台设备在线 | 设备模拟联调区：温度 15–35 ℃、相对湿度 ≤ 80 %RH |
| s02 装样并核对各样本设定温度 | 人工（核对样本） | 勾选已按方案核对每个样本的设定温度 | — |
| s04 温控器设定温度 | 设备（ST-PF-OPCUA，`cap.tc_setpoint`，设备方法） | 按样本依次写设定温度、回读 | ST-PF-OPCUA 压力 0.5–10 bar，加上实验区温度、湿度 |
| s05 环境箱设定温度 | 设备（ST-PF-HTTP，`cap.chamber_setpoint`，设备方法） | 按样本依次写设定温度、回读 | 实验区温度、湿度 |
| s06 QA 复核运行数据 | 审核（QA） | QA 批准 | — |

步骤编号沿用原来的：s03 是删掉的「PLC 控温运行」，不复用（从旧流程出修订版时，同一个编号还指同一步）。两个设备步骤的
`temp` 在流程里写 60 ℃，只是缺省值，方案的因子会按样本改写。每步关联 SOP-PF-01 对应的步骤。

### 多温度矩阵方案

方案类型「矩阵」，两个因子各落到一个设备步骤的 `temp` 参数：

| 因子 | 水平（℃） | 落到 |
|---|---|---|
| 温控器设定温度 | 40、60、80 | s04 `temp` |
| 环境箱设定温度 | 40、60、80 | s05 `temp` |

设计点是 `[[40, 40], [60, 60], [80, 80]]`：两个因子对齐成「每个样本一个温度」，而不是 3 × 3 的全组合。
3 个设计点 × 1 次重复 = 3 个样品（A1、A2、A3）。批次里每个设备步骤是**一条指令**，参数带逐孔温度：

```json
{"temp": 60, "wells": {"A1": {"temp": 40.0}, "A2": {"temp": 60.0}, "A3": {"temp": 80.0}}}
```

驱动按 A1、A2、A3 的顺序一孔一孔跑，每孔有自己的运行号（`<指令号>/<序号>`）。提交时先把每一孔的整套启动拼一遍，
有一孔拼不出来就整条拒绝、设备一次都没动；某一孔没做成，整条指令到此结束，结论写明是第几孔、后面几孔没有执行。

## 看结果

- **批次管理 → 批次详情**：两个设备步骤的检查点里是逐孔回报（`delivered.wells`，`real:sila2_v1`）。
- **数据审核 / 结果分析**：一个样品两条结果，温控器、环境箱的回读温度等于各样本的设计温度（40 / 60 / 80）。
- **环境监测**：设备模拟联调区的温度、相对湿度（来源 `device:ST-PF-MB`）与 ST-PF-OPCUA 的压力（`device:ST-PF-OPCUA`），
  每 30 s 一条。
- **报告管理**：已发布的批次报告。

脚本最后会逐样本打印设计温度和两台设备的回报，例如：

```
✓ A1 S261006001-A1：设计 40 ℃ → 温控器 40.0 · 环境箱 40.0
✓ A2 S261006001-A2：设计 60 ℃ → 温控器 60.0 · 环境箱 60.0
✓ A3 S261006001-A3：设计 80 ℃ → 温控器 80.0 · 环境箱 80.0
```

## 演练环境不满足时

- 把温湿度传感器的湿度改到 80 以上（ProtoForge 界面，或 ST-PF-MB「设备连接 → 点位」签名手动写 `humidity`；传感器的可写范围
  30–80 %RH，要演练超限就在 ProtoForge 里改），等下一次采集：新批次的开跑检查不放行，写明「设备模拟联调区 相对湿度高于要求 80」；
  已经下发的批次在设备步骤投递前同样被拦下。演练建的批次在批次管理里退回待排程、签名终止；湿度写回 50 后下一次采集就恢复。
- OPC UA 的压力高于 10 bar 或低于 0.5 bar：温控器那一步的环境要求不满足，开跑检查与它投递前都被拦下。
- 停掉驱动宿主（`docker stop ilcs-driver-host`）：三台设备离线、读数不再更新，超过环境读数时效后开跑检查报读数过期；
  执行门挡住三台设备。
