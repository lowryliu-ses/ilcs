# 操作案例：从零走到一份已发布报告

对着 **http://10.10.106.51:8090** 做。口令一律 `ilcs1234`。

这个案例覆盖一条完整闭环：补齐执行前置主数据 → SOP → 方法 → 方案审批 → 任务 → 批次四类节点 → 检测与数据复核 → 报告发布。全程在界面上完成，不需要碰数据库，也不需要用接口补步骤。

每一步都注明**换哪个账号**，因为多处规则是「提交人 ≠ 审批人」——同一个人做不完。建议开两个浏览器窗口（一个普通、一个隐身）分别登两个账号，省得反复切换。

预计耗时 30–40 分钟，其中有一处要等 30 分钟（等待节点），案例里给了绕过办法。

## 阶段 0：先解锁执行（`admin`）

线上现在**下发不了任何批次**，这是刻意的：迁移不编造资质与校准。开跑检查会明确告诉你缺什么。先把这两样补上。

### 0.1 给操作员授资质

1. 左侧 **资源 · 人员与资质**
2. 找到 `P-OPERATOR 操作员` 一行 → 点 **资质**
3. 点 **登记资质**，按下表加。**每次只加一条，加完再点一次**：

| 资质类别 | 范围 | 说明 |
|---|---|---|
| 设备能力 | 控温匀浆 `cap.mix` | 案例里的设备节点要用 |
| 设备能力 | 扣电组装 `cap.assemble` | 线上那两个旧批次要用 |
| 安全类别 | 填 `危化品操作` | 人工称量节点要用 |

有效期留空表示长期有效；填了日期，系统按**预计执行时间**判定，不是按今天。

4. 回到列表，「资质」列应显示 `有效 3/3`，「可执行系统任务」列是 `可分配`

> 资质是签字背书的事实。这一步你填的是你们实际的授权记录，系统不替你猜。

### 0.2 给设备登记校准

1. 左侧 **资源 · 仪器设备**，现在有 8 台（按工位补录的，名称型号都来自原工位台账）
2. 找 `AS-ST-01-A 高通量匀浆站 A` → 点 **详情** → **登记校准**
3. 填：结果 `合格`、到期日填一个未来日期、**上传校准证书**（随便一个 PDF 都能走通流程）
4. 关闭对话框，列表里「校准」列应从 `缺失或过期` 变成 `有效`，「不可用原因」变成 `可用`

**合格校准必须附证书**，不传证书会被拒（`certificate_required`）。这是故意的：一条没有证书的合格记录就是一份伪造的计量背书。

如果某台设备本来就没有计量输出（手工工作台一类），改走另一条路：列表里点 **编辑** → 取消勾选「需要校准」→ **写明理由**（缺失不等同不适用，理由必填）。

案例只用到匀浆站，先给 `AS-ST-01-A` 登记一条就够。

## 阶段 1：设计（`researcher` + `qa`）

### 1.1 建一份 SOP 并发布

`researcher`：

1. **设计 · SOP** → **新建版本**
2. 编号 `SOP-CASE-01`、标题 `案例用作业指导书`、版本留空（自动编号）
3. 「适用能力」勾 **控温匀浆**
4. 勾上「执行相关节点前必须有该版本的阅读确认」——后面能看到它怎么卡下发
5. 上传附件（任意 PDF），点 **创建草稿**
6. 列表里点 **详情** → **提交评审**（没有附件时这个按钮是灰的）

`qa`：

7. 同一页 → **详情** → **批准并发布**（要签名，输一次口令）

`researcher` 或将来的执行人：

8. **详情** → **阅读确认**（因为第 4 步勾了培训要求）。没有这一步，用到它的批次下发会被挡住。

### 1.2 建方法并发布

`researcher`：

1. **设计 · 方法与配方** → **新建草稿**，名称 `案例流程`
2. 列表里点 **编辑**（或进详情页点 **图形化编辑**）
3. 右侧默认是「方法属性」面板：
   - **关联受控 SOP** 选刚发布的 `SOP-CASE-01`
   - 风险评估编号填 `RA-CASE-01`
   - 「每批物料需求（BOM）」里加一行：`NCM811 正极粉`，数量 `20`
4. 左侧节点面板加四个节点，顺序如下（点节点卡片上的「添加」，加完在画布上点它编辑参数）：

| 序 | 类型 | 怎么加 | 关键设置 |
|---|---|---|---|
| 1 | 人工 | 点「+ 人工」 | 名称`称量备料`；记录表单加一个字段：标识 `weighed_g`、名称 `实际称量质量 g`、类型 数值、必填；勾「需要签名」；勾「消耗物料」 |
| 2 | 设备 | 点「控温匀浆」的「添加」 | 浆料温度 `25`、匀浆转速 `2000`、时长 `5` 分钟 |
| 3 | 等待 | 点「+ 等待」 | 方式 固定时长、时长 **1** 分钟（**别用默认的 30，否则你要等半小时**） |
| 4 | 审核 | 点「+ 审核」 | 审核角色 `qa` |

5. 右上 **保存草稿**，看右侧校验清单前五项是否都通过
6. **保存并提交评审**

`qa`：

7. **方法与配方** → 点进 `案例流程` 的 **详情** → **批准** → 再 **发布**（两步都要签名）

> 只有「已发布」的方法能被方案引用。

### 1.3 建方案并审批

`researcher`：

1. **设计 · 实验方案** → **新建方案**
2. 名称 `案例方案`、方法选 `案例流程`、类型选 **单条件**（矩阵类型要定义两个因子，案例用不上）
3. **创建草稿** → 自动进详情页
4. 点 **编辑方案**（矩阵类型时这个按钮叫「编辑因子」），重复数填 `2`（会生成 2 个样本），保存
5. 点 **锁定结构**
6. 点 **提交评审**

`qa`：

7. 同一页 → **批准**（要签名）

**锁定 ≠ 已审批。** 只锁定不审批，下一阶段建批次会被拒（409 `plan_not_approved`）。想看这条规则生效，可以在第 5 步之后先去建批次试一次。

## 阶段 2：执行（`researcher` → `operator` → `qa`）

### 2.1 建任务并分配

`researcher`：

1. **执行 · 任务中心** → **建立任务**，方案选 `案例方案`，优先级 `1`
2. 列表里点进任务 → **分配** → 执行人选 `操作员`

分配时按**预计执行时间**校验资质。阶段 0.1 没做的话，这里会直接告诉你缺哪项资质。

`operator`：

3. **任务中心**（默认只看「我的」）→ 点进任务 → **接单**

### 2.2 建批次、排程、下发

`operator`：

1. **执行 · 批次** → **新建批次**，方案选 `案例方案`、任务选刚接的那个，备注随便写
   - 创建成功时会提示「物料已按 BOM 预留」。去 **资源 · 试剂耗材** 能看到 `NCM811 正极粉` 的**可用量**少了 20 g，**账面库存没变**——预留占用的是可用量，不是账面。
2. 列表里点 **排程**
3. 点进批次详情 → **开跑检查**。九项逐条给结论，三态：通过 / 阻塞 / 不适用
   - 纯人工节点不会被「没有可承接工位」挡住，这类项显示「不适用」
   - 若有阻塞，按提示回去补；每条都写明了缺什么
4. 勾「已完成人工复核」→ 点 **签名并执行**（输口令）

### 2.3 走完四类节点

`operator`：

1. 详情页第 1 步（人工）点 **填写记录**
2. **先直接点提交试一次**：会被拒，并逐条列出缺哪项——缺项不推进
3. 填上质量数值，勾上样本核对与物料核对，点 **签名并提交**
4. 第 2 步（设备）**不用管**：执行器会自己领指令、跑完、写检查点。5 分钟；刷新页面能看到它从「运行中」变「已完成」，检查点 +1
5. 第 3 步（等待）到期后由**后台推进器**唤醒，不需要你刷新页面——刷新只是让你看到结果。等 1 分钟

`qa`：

6. 第 4 步（审核）点 **审核**
   - **先用 `operator` 试一次**：提交人不能审核自己的记录，会被拒
   - 换 `qa` → 结论「通过」→ 签名。批次随后变「已完成」

## 阶段 3：数据与报告（`researcher` + `qa`）

批次跑完了，但**还没有任何可用数据**——采集完成、质量有效、审核通过是三件事。

### 3.1 建检测任务

`researcher`：

1. **科学数据 · 数据审核**，往下翻到「检测任务」面板 → **建检测任务**
2. 样本选批次生成的那个（编号形如 `S2609xxxxx-A1`）
3. 检测方法填 `电性能测试`、方法版本填 `EC-02 v2`
4. 「要求指标」勾 **面密度** 和 **首次放电比容量**
5. **建立**

要求指标在建任务时**冻结**：之后只有这两个指标的结果能入账，补测别的要另建任务。指标清单来自 **治理 · 指标定义**（线上已有 4 个种子指标；不够用就在那一页登记）。

### 3.2 录入结果

两条路，选一条：

**A. 人工录入**（没对接 LIMS 的仪器走这条）

1. 检测任务那一行点 **录入结果**
2. 两个指标各填一个数（如 `22.1` 和 `205`），点 **录入**
3. 状态变「已采集」，但审核仍是「待复核」

测不到的指标请在「测不到的原因」列写原因，**不要填 0**——缺测和 0 是两件事。

**B. 仪器/LIMS 回传**（看服务认证怎么走）

在任意能访问的机器上执行，`TASK_ID` 用任务列表里显示的完整 ID：

```bash
curl -X POST http://10.10.106.51:8090/api/integrations/results \
  -H 'Content-Type: application/json' \
  -H 'X-Service-Source: lims-ec' -H 'X-Service-Secret: ilcs-lims-dev-secret' \
  -d '{"event_id":"case-001","task_id":"TASK_ID","parser_version":"ec-parser 2.1",
       "metrics":[{"metric_version_id":"METRIC-areal_density-v1","value":22.1,"unit":"mg/cm2"},
                  {"metric_version_id":"METRIC-discharge_capacity-v1","value":205,"unit":"mAh/g"}]}'
```

同一个 `event_id` 重发一次，会返回 `"replayed": true` 并回放原结果，不会记成第二条。去掉两个 `X-Service-*` 头再发，得 401——没有匿名回传这条路。

> 线上的服务口令还是种子里的。正式使用前请到 `/api/service-identities` 重新签发，口令明文只在签发响应里出现一次。

### 3.3 逐条复核

`qa`（**不能是录入人自己**）：

1. **数据审核** 上半部分「结果明细」，筛选「待复核」
2. 每条点 **审核** → 结论「通过」→ **还要给质量判定**：有效 / 可疑 / 无效
3. 把其中一条判成 **无效**，写个理由（如「首片边缘缺陷」）——下一步能看到它怎么被排除

「审核通过」和「质量有效」是两个字段，必须都给。只审不判定，服务端会拒。

### 3.4 出报告

`researcher`：

1. **科学数据 · 报告** → **生成报告**，批次选案例批次，写结论
2. **生成草稿** → 点 **详情** 看内容：
   - 「统计」里，被你判无效的那条**不在均值里**
   - 「排除说明」里有它，理由写着「已审核但质量判定无效」
3. 点 **提交审核**
4. **先用 `researcher` 自己点批准试一次**：作者不能批准自己的报告，403

`qa`：

5. **批准**（签名）→ **发布**（再签一次）
6. 点 **下载**。发布时固化了：结果版本清单、算法版本、模板版本、PDF 摘要、签名。之后报告只读，改不了

## 这个案例顺手证明的规则

| 你会撞到的拒绝 | 为什么 |
|---|---|
| 锁定但未审批的方案建不出批次 | 矩阵锁定只是结构冻结，不是审批结论 |
| 人工节点缺项不推进 | 记录不全就没有「这一步做过了」这回事 |
| 提交人不能审核自己的记录 / 作者不能批准自己的报告 | 四眼原则，服务端判，界面藏不了 |
| 无证书的合格校准被拒 | 一条没有证书的合格记录就是伪造的计量背书 |
| 不适用校准必须写理由 | 缺失不等同不适用 |
| 无服务凭据的回传 401 | 没有匿名兼容路径 |
| 采集完成的结果不进统计 | 采集完成 ≠ 质量有效 ≠ 审核通过 |
| 审核通过但判无效的结果被排除并写明理由 | 正式统计要三者同时成立 |
| 已发布的报告改不了 | 发布即固化 |
