# 操作案例：注液、循环测试，以及用 AGV / 机械臂把两者串起来

三个案例，每个都从设计流程一直走到发布报告：

| 案例 | 测什么 | 用到的设备 | 重点看什么 |
|---|---|---|---|
| **A 注液** | 4 个注液量 × 2 次重复，共 8 个扣电 | ST-05 干燥称重 → **ST-06 配液站（SiLA 2）** | 一条指令带全部孔位的注液量；设备回报每孔实测量；库存按实测量扣；逐孔质检；人工记录与 QA 审核 |
| **B 循环测试** | 0.5C / 1C 各 4 个扣电，化成 1 圈 + 循环 50 圈 | **ST-07 充放电柜（SiLA 2，8 通道）** | 循环测试按已发布的**设备方法**执行（设备端程序、缺省参数与必报数据）；圈数、倍率下发到设备；等待节点由后台唤醒；按放电容量质检；无效数据不进正式统计 |
| **C 串行** | 注液量 50 / 60 μL × 循环倍率 0.5 / 1C，各 2 个 | 板库 → ST-05 → ST-06 → ST-07，**AGV 转运托盘，机械臂协同上下料** | 托盘绑定批次后，系统在每个换工位的设备步骤前自动生成 AGV 转运指令，转运确认完成后设备才动作；注液步骤与机械臂同起同止 |

对着本地 **http://127.0.0.1:8090** 或远端 **http://10.10.106.51:8090** 做，两边是同一套数据（只有批次号里的日期不同）。账号口令一律 `ilcs1234`，每次电子签名输入的也是**当前登录账号自己的**这个口令。

建议开两个浏览器窗口（普通窗口 + 隐身窗口）：一个登 `researcher` / `operator`，另一个登 `qa`。「提交人 ≠ 审批人」的规则很多，一个账号做不完。

- 案例 A 约 30 分钟，B 约 30 分钟，C 约 25 分钟（C 里的通用环节和 A、B 一样，熟了会快）。
- 设备真实执行的时间：配液站每次约 20 秒，充放电柜每次约 60 秒。流程里写的 60 min、120 min 是计划时长，设备提前完成后系统会把后面的时间窗整体提前，不用干等。

## 二、三个案例都要走的通用环节

后面每个案例只写「填什么」，按哪个顺序点在这一节。第一次做案例 A 时对照这一节走一遍，后面就熟了。

### G1 建流程并发布（`researcher` → `qa`）

`researcher`：

1. **实验设计 · 实验流程** → **新建草稿**：填名称，每批样品位数填 `8`，「复制步骤自」选**不复制** → **创建**。
   > 想跳过画流程，可以在「复制步骤自」选对应的参考流程，直接进下一步看它的校验；但第一次建议自己画。
2. 进流程详情 → **图形化编辑**。
   - **设备步骤**：左侧节点面板按能力分组，在能力卡片上点 **添加**（或拖到画布上）。
   - **人工 / 等待 / 审核 / 质检关卡**：点「流程节点」下的 **+ 人工**、**+ 等待**、**+ 审核**、**+ 质检关卡**。
   - 新节点接在当前选中节点后面。点画布上的节点，右侧属性面板编辑；点「流程属性」回到流程级设置。
3. **先**点「流程属性」，**关联受控 SOP** 选 `SOP-EC-02 … v2`，填**风险评估编号** `RA-205 v2`；在「物料需求 BOM」里按案例填（没有就不填）。先关联 SOP，节点属性里的「对应 SOP 步骤」下拉才有选项。
4. 按案例里的步骤表逐个填好，每个节点的**对应 SOP 步骤**按下表选（表里没有的选「不对应」）。右侧「校验」清单要全部打勾，其中「关联 SOP 版本」一项显示 SOP 名称与版本。

| 节点 | 对应 SOP 步骤 |
|---|---|
| 极片真空干燥 | 第 1 步 |
| 称重选片 | 第 2 步 |
| 注液封口 | 第 4 步 |
| 封口外观与开路电压检查（案例 A） | 第 5 步 |
| 化成后静置 / 注液后静置浸润 | 第 6 步 |
| 化成（0.1C 首次充放电） | 第 7 步 |
| QA 审核节点 | 第 8 步 |
| 扣电上柜与夹具检查、循环测试、质检关卡 | 不对应 |
5. **保存草稿** → **保存并提交评审**。

`qa`：

6. 同一流程详情 → **批准**（签名）→ **发布**（签名）。
   - 签名框：「签名含义」保持默认，口令填 `ilcs1234`。
   - 可以先用 `researcher` 点批准试一下：作者 / 提交人不能批准自己的流程。

### G2 建方案并批准（`researcher` → `qa`）

`researcher`：

1. **实验设计 · 实验方案** → **新建方案**：
   - 从模板创建：不用模板
   - 名称：按案例
   - 方案类型：矩阵实验
   - 所需检测指标：按案例多选（按住 ⌘ / Ctrl 点选）
   - 实验流程：选你刚发布的流程
   - 研究目标、重复次数：按案例；孔位布局：顺序
2. 进方案详情 → **编辑因子** → **添加因子**，逐项填：因子名称、单位、水平（**添加水平**）、**作用于设备参数（可选）**、**物料换算（可选）** → **保存**。
   - 「作用于设备参数」选了某一步的某个参数，建批次时每个孔位的水平就冻结进批次，下发时**一条设备指令带上全部孔位的参数**。不选则水平只区分样本，设备按流程里的固定参数执行。
3. 看「结构校验」全部打勾；看「条件矩阵」的孔位分配和「物料需求预览」。
4. **锁定矩阵** → **提交评审**（审批级别保持默认的一级「QA 审批」）→ **提交**。

`qa`：

5. 方案详情 → **批准**（签名）。状态变成「矩阵已锁定 · 审批：已批准」。锁定只是结构冻结，**批准之后**才能建任务和批次。

### G3 任务 → 批次 → 排程 → 开跑检查 → 下发（`researcher` → `operator`）

`researcher`：

1. **工作台 · 任务中心** → **建立任务**：选你的方案，优先级 P2 → **建立**。
2. 点任务编号进详情 → **分配** → 选「操作员」→ **分配**。分配时按预计执行时间核对资质。

`operator`：

3. 任务中心 → 同一任务 → **接单**。
4. **执行与监控 · 批次管理** → **新建批次**：选方案和刚接的任务 → **创建并预留物料**。批次、8 个样本孔位、物料预留在同一个事务里生成。
5. （仅案例 C）进批次详情 → 「载具与位置」→ **绑定载具**（见案例 C）。必须在排程之前或排程后下发之前绑定。
6. 回批次列表点 **排程**。去 **执行与监控 · 排程** 看各工位的时间窗。
7. 批次详情 → **开跑检查**：逐项看结论（设备校准与占用许可、首工位与后续工位执行许可、执行人资质与时间预占、受控 SOP、计划开始时间……，不适用的项会标出来）。「受控 SOP」一项应为通过（SOP-EC-02 v2 生效中、样本类型在适用范围内）；「执行人资质」一项同时核对执行人（操作员）对这版 SOP 的阅读确认。勾「已完成人工复核」→ **签名并执行**。

### G4 执行中要人做的节点

- **作业指导**：批次详情有「作业指导 · SOP SOP-EC-02 v2」面板：下载开批时固化的 SOP 附件，逐步看说明与核对项。工步表里对应了 SOP 的节点带「SOP 第 N 步」标记。执行中 SOP 发了新版本，这个批次仍按开批时固化的版本执行。
- **人工节点**（`operator`）：批次详情「工步」表里该步出现 **填写记录**（也会出现在任务中心「我的人工待办」）。弹窗顶部显示对应 SOP 步骤的说明与核对项；按表单填，勾核对项；要求签名的会弹签名框。
  - 可以先不填直接提交一次：服务端拒绝并逐项列出缺什么，流程不推进。
- **审核节点**（`qa`）：任务中心「待流程审核」或批次详情里点 **审核** → 结论「通过」→ 签名。
  - 先用 `operator` 点一次：提交人不能审核自己的记录。
- **设备、等待、质检关卡**：系统自己走。设备由执行器投递；等待到期由执行器唤醒（不刷新页面也会推进）；质检关卡读上游设备回执里的测量值自动判定。

## 五、案例 C：注液 → 循环测试串行（AGV 转运 + 机械臂协同）

**目的**：一个批次从注液一路做到循环测试。8 个样本装在托盘上，托盘绑定批次后系统追踪它的位置：每个设备步骤开始前，托盘不在这个工位，系统先生成一条转运指令发给 AGV，**转运被确认完成后设备才收到动作**；注液时手套箱机械臂作为协同资源一起占用。

## 六、这三个案例证明的规则

| 你看到的 | 为什么 |
|---|---|
| 矩阵因子按孔位写进设备指令，一条指令带全部孔位参数 | 条件真的到达设备，不只写在方案里 |
| 库存按设备回报的实测量扣减 | 账上记实测量，计划量只作对照；偏差超 5% 报警待复核 |
| 质检关卡读设备回执里的测量值，取不到值不放行 | 没有数值不等于合格 |
| 等待节点到期不刷新页面也会推进 | 推进由执行器负责，不靠浏览器 |
| 托盘不在工位时先转运，转运确认后设备才动作 | 板没到位，设备收不到指令 |
| 协同资源与主设备同起同止，一个被占就整体等 | 不会只占到一半就开工 |
| 提交人不能审批自己的流程、方案、记录、数据和报告 | 职责分离 |
| 流程能力超出 SOP 适用范围不能发布；执行人没读过 SOP 不能下发；批次按开批时生效的 SOP 版本固化 | 受控文件真正管到执行 |
| 判为无效的数据不进统计，报告自动列出排除说明 | 采集完成 ≠ 质量有效 ≠ 审核通过 |

## 附录：故障演练（可选）

在 `deploy/` 目录执行，模拟器容器里自带注入命令。**每项演练完都要执行 `none` 恢复**，故障是持续生效的。

### 公共保护联锁 → 全站停

```bash
docker compose exec sila-sim-lh python simulators/sila_device/fault.py interlock
```

约 10 秒后顶栏执行门变为关闭，原因「ST-06 公共保护联锁未解除」。排程、下发、续跑一律被拒，保持和终止仍可执行。恢复：

```bash
docker compose exec sila-sim-lh python simulators/sila_device/fault.py none
```

### 设备掉线 → 只挡这一个工位

```bash
docker compose exec sila-sim-lh python simulators/sila_device/fault.py offline 60
```

执行门仍开放，ST-06 被列为阻塞工位：用到 ST-06 的批次（案例 A、C）下发被拒，案例 B 照常。60 秒后探测恢复，自动转回在线。

### 回执丢失 → 结果未知，不重发

1. 用案例 A 的方案再建一个批次并排程，**先不下发**。
2. 注入：

```bash
docker compose exec sila-sim-lh python simulators/sila_device/fault.py lost_receipt
```

3. 下发。第 1、2 步照常完成；第 3 步的指令变成**结果未知**，批次转故障挂起，执行器不会重发这条注液指令。
4. 恢复模拟器后查设备侧：`executions` 里这条指令是 `1`，设备只动作了一次。

```bash
docker compose exec sila-sim-lh python simulators/sila_device/fault.py none
docker compose exec sila-sim-lh python simulators/sila_device/fault.py state
```

5. 界面上这条指令旁点 **现场核查**，按现场看到的下结论并签名：已执行（按人工核实写检查点，流程继续）/ 未执行（可在恢复评估里续跑）/ 部分执行（只能终止）。

其他故障模式（`slow_submit`、`stuck`、`fail`、`partial`、`busy`、`clock_skew`、`no_dedup`）见 [simulators/sila_device/README.md](../simulators/sila_device/README.md)。
