版本：1.0  
日期：2026-09-21  
适用代码目录：`/Users/lowry/Downloads/UI/ilcs`  
依据：同目录《实验室平台修订方案.md》v4，以及其后确认的评审修正。  
用途：在现有 ILCS 上拆分开发任务、编写接口与数据库设计、实施增量改造和验收。

本次开发将现有批次中控系统扩展为能够管理资源准备、实验方案、人工与设备混合执行、样本流转、数据审核和报告归档的平台。首期交付现有问题修正、基础模型与权限、一类代表性实验的完整流程；第二、三期保留明确范围，另行细化任务。

本文所称“现有”来自本地代码静态核验，不表示线上已验证或真实设备已接入。当前目录没有可读取的 Git 提交基线；开发启动时应建立版本基线、保存数据库副本及配置清单。本文提供的新增模型、接口和状态是开发要求，不是现有能力。

## 1 文档约定和本次决策

### 1.1 开发约定

- “必须”表示交付和验收要求；“首期”包含下文 M0、M1、M2、M3；不以仅完成页面作为完成标准。
- 需求用 `DEV-01` 至 `DEV-16` 标识，验收用例用 `AC-01` 至 `AC-40` 标识。后续迭代需求用 `FUT-01` 至 `FUT-10` 标识。
- 代码路径除特别说明外均相对于上述代码目录。新增路径是建议落点，允许同层内调整；分层职责和业务约束不可绕过。
- 数据表字段是最低业务契约，不要求逐字采用物理表名；实现前须提交包含类型、外键、索引和约束的迁移设计。
- 接口清单中所有路径均带 `/api` 前缀；现有接口原位扩展，新增接口先更新 OpenAPI 契约再与前端联调。
- 需求未明确的设备动作、物料有效期限、历史审核结论，不得由系统自行猜测。

### 1.2 对 v4 的明确修正

| 项目 | 本文采用的要求 |
|---|---|
| 库存去重 | 复用统一事件与幂等机制，同时在库存流水建立业务事件唯一约束；覆盖设备、人工、称量及退回，不只依赖设备命令 |
| 正式统计 | 同时满足审核通过、质量有效、选定版本；审核完成不等于质量有效 |
| 正式报告 | 禁止纳入未审核数据；无效或可疑数据可列为被排除记录并说明原因，不进入正式统计 |
| 真实设备 | 首期包含一台真实设备试点；待确认的是具体设备、接口、现场条件和验收时间，不以模拟运行替代真实验收 |
| 回传验收 | 以本文完整用例清单为准，不再使用“通过五种情况”等固定数量表述 |

### 1.3 首期建议场景及边界

建议采用“单条件样本实验”作为开发和联调样例：方案建档并审批 → 样本登记或从方案生成 → 分配有资质人员 → 人工备料与记录 → 设备执行 → 定时等待或检测 → 分批回传指标 → 复核 → 生成并发布报告。该场景用于定义产品行为，不代表需求方已选定具体实验。

保留现有矩阵实验作为兼容性回归场景；委托检测首期支持既有样本和固定方法的基础流程，完整抽样请验业务放入第二期。首期支持人工、设备、等待、审核四类顺序节点，不做任意脚本、条件图、并行分支和通用流程设计器。

## 2 交付范围和里程碑

| 里程碑 | 交付范围 | 出口条件 |

完整平台所需能力不等于首期全部交付。采购、复杂培训、稳定性考察、完整安全运营、AGV 和 AI 不作为 M3 的隐含验收项。

## 4 角色与业务权限

保留现有静态角色字典并增加动作权限；组织范围、资质和职责分离在服务端独立校验。以下为新增功能的默认权限，不扩大原有设备控制权限。

| 角色 | 首期新增职责 |
|---|---|
| 研究员 researcher | 编写方案、方法及报告草稿；分配实验任务；录入和提交实验数据；查看授权项目数据 |
| 操作员 operator | 接单、执行人工节点、登记样本与流转、投料和耗用记录；按现有权限操作批次 |
| QA qa | 复核数据、批准方案和报告、批准 SOP、授权更正；审核本人录入或编写的内容必须被拒 |
| EHS ehs | 维护物料安全属性及相关资质记录；按现有权限处理报警、物料和危废 |
| 管理员 admin | 人员、资质、组织成员、设备、集成凭据和主数据配置；具备相应业务动作权限时仍不得绕过本人审批限制 |
| 集成服务身份 | 仅提交授权任务的结果、授权设备的心跳与回执；不获得人类用户的管理权限 |

资产管理员、样本管理员等首期作为现有角色的职责，不新增动态权限组编辑器。任务分配人和执行人通过稳定用户 ID 关联，显示名称变化不改变历史身份。

## 5 详细开发需求

### DEV-01 版本化迁移与数据库基线

1. 引入 Alembic，建立现有结构基线和新增模型迁移；支持已有 SQLite 数据导入 PostgreSQL，导入与结构迁移分开记录。
2. 移除 API 与 executor 启动时的自动建表、补列和生产自动播种；迁移作为部署单独步骤，种子仅用于显式初始化或测试。
3. PostgreSQL 是正式多人使用和真实设备试点的验收数据库；SQLite 可保留作轻量开发环境，但不能代替并发验收。
4. 样本、结果和历史批次保留稳定 ID、版本与引用；迁移报告列出记录数、关联完整性、数量余额、异常记录及处理方式。
5. 旧 `valid` 不能自动迁移成“审核通过”，旧库存不能按模拟比例消耗批量倒扣；按第 10 节建立历史标记与期初余额。
6. 多副本发布使用同一数据库迁移版本；应用版本不兼容时拒绝进入可用状态，不能自行修改结构。

代码：`api/app/core/db.py`、`api/app/core/migrate.py`、`api/app/models/`、`api/app/main.py`、`executor/main.py`、新增 `api/alembic/`、`scripts/` 和 `deploy/`。验收：AC-01、AC-02。

### DEV-02 组织归属与访问控制

1. 增加组织、实验室、项目、组织成员关系；样本、方案、方法、批次、任务、结果事件、报告、文件、库存和资源记录具有明确归属，或者通过受约束的父对象确定唯一归属。
2. 用户登录后只能选择所属组织；服务端校验当前成员关系，不能仅凭请求体中的 `organization_id` 授权。现有登录令牌需要兼容升级与失效处理。
3. 统一为仓储和服务传递访问上下文；列表、主键读取、修改、关联、导出、统计、下载及审计查询均校验范围。跨组织对象直接访问返回 404；已知资源上的无动作权限返回 403。
4. 任务、样本、批次及其附件的关联不得跨组织。后台任务从持久化任务确定组织，禁止使用自动绕过过滤的全局身份。
5. 首期默认组织内可见、按角色控制动作；启用受限项目时，通过项目成员关系控制访问，关联样本、结果与报告继承项目访问范围。真实业务启用前确认是否需要此模式；跨组织隔离在任何模式都必须生效。
6. 首期设备仅归属一个组织；跨组织共享设备不默认开放，后续有明确共享授权再启用，调度只暴露必要占用信息。

代码：`api/app/models/identity.py`、`api/app/api/deps.py`、`api/app/core/security.py`、`api/app/repositories/base.py`、各业务仓储及聚合服务、`web/src/shared/session.tsx`。验收：AC-03、AC-04。

### DEV-03 服务身份、统一事务与幂等

1. 结果回传、设备心跳及新增设备回执入口使用独立服务凭据；关联组织、可操作设备和可提交检测任务范围，支持停用和轮换。数据库保存凭据摘要，日志不记录凭据原文。
2. 回传来源由认证确定；仪器序列号等可作为业务数据传入，但必须校验与授权设备一致，不能用其代替来源认证。
3. 幂等键作用域包含组织、调用主体、操作及键值；保存规范化请求摘要与原响应。相同键且内容一致返回原响应，不重复变更；内容不同返回 409。
4. 正式前端对新建、提交、审批、库存入账和控制动作发送稳定幂等键。网络重试复用原键，不生成新键；首期内部客户端同步升级。无可靠业务键的上述关键写接口缺少幂等键时拒绝。
5. 设备回传以业务事件键去重，事件编号必填；不存在匿名或缺少事件编号的正式回传兼容旁路。旧集成须通过适配层补齐来源和稳定事件编号后切换。
6. 统一事务以业务用例为边界：业务数据、成功审计和幂等记录同事务提交；底层服务不能提前 commit。并发冲突由数据库唯一约束及行级并发控制处理，不能只做先查询再插入。
7. 同一事件若产生多个业务明细，事件整体成功或整体失败。事务提交失败不能留下完成任务或已消费签名；拒绝事件另写访问日志，不制造成功业务审计。
8. 执行器内部调用使用显式受限系统上下文，不能因加强 HTTP 认证破坏模拟流程，也不能通过伪装人类用户绕过权限。

代码：`api/app/api/deps.py`、`api/app/models/governance.py`、`api/app/repositories/governance.py`、各服务提交点、`api/app/api/routers/results.py`、`api/app/api/routers/stations.py`、`web/src/shared/api.ts`。验收：AC-05 至 AC-08。

### DEV-04 文件和原始数据

1. 首期提供真实文件上传、按权限下载、关联、摘要校验、备份恢复；开发默认受控目录，存储接口可替换为对象存储。文件数据置于持久卷，不放前端静态目录。
2. 文件记录包括所属组织、关联对象、原文件名、媒体类型、字节数、内容摘要、存储键、上传主体、时间及状态。存储键由服务端生成，不能由用户拼接物理路径。
3. 初始允许 PDF、CSV、XLSX、PNG、JPEG，单文件上限默认 20 MiB，可配置；应用与反向代理上限同步。真实仪器其他格式须列入试点配置，不静默丢弃大文件。
4. 上传中、可用、失败分状态处理；文件写入失败不得留下“可下载”记录。使用受控清理任务处理未关联临时文件，已被报告或审核记录引用的文件不可物理删除。
5. 原始数据下载读取真实文件；历史模拟曲线保留“模拟数据”标签，不能包装成真实采集原件。首期禁止服务器任意抓取调用方传入的外部 URI；外部文件先上传或使用经过配置的存储连接器。
6. 全部下载，包括报告和 SOP，必须经过对象访问校验；记录访问审计。备份必须同时覆盖文件和引用它们的数据库记录。

代码：新增 `api/app/models/file.py`、`api/app/services/file_service.py`、文件存储接口及 router；修改 `api/app/services/result_service.py`、部署卷和 nginx 配置。验收：AC-09。

### DEV-05 人员档案和资质

1. 在账号之外建立人员档案，包含姓名、所属实验室、在岗状态、联系方式、可选账号关联；首期只允许绑定有效账号的人员执行系统任务。
2. 资质记录包含人员、适用能力或 SOP 版本、证据文件、授予者、生效时间、到期时间、撤销状态；资质类型支持设备操作和安全操作。
3. 分配任务时按预计执行时间校验，实际开始与恢复时再次校验。到期、撤销、停用账号均阻止新的相关操作；不能因为是管理员而绕过资质。
4. 已运行设备上的人员资质变化不自动执行物理急停；产生告警并阻止下一受控操作，现场动作遵循设备和已批准的恢复规则。
5. 首期做档案列表、详情、资质维护、到期提醒和任务分配提示；培训课程、考试评分和批量培训计划后移。

代码：扩展 `api/app/models/identity.py`、`api/app/services/identity_service.py`、新增人员 router 和 `web/src/features/people/`。验收：AC-10。

### DEV-06 设备档案、校准维护与预约

1. 新增资产档案：资产号、名称、型号、序列号、组织、实验室、责任人、位置、状态；关联现有 Station。支持无适配器的仪器和手工工作台。
2. 校准记录包含适用设备或能力范围、结果、生效及到期时间、证书、登记人；只有有效且合格的记录构成许可。明确“不适用校准”的资源不强制证书，缺失不能等同不适用。
3. 维护和人工预约使用资源占用记录，包含起止时间、资源、原因、状态及创建人；与自动排程共用冲突判断，确认时在事务中重新校验。
4. 一台资产映射多个工位时，共享资产级容量约束；首期默认一份独占容量。确可独立并行的通道必须有显式配置，不能因工位 ID 不同就重复占用同一设备。
5. 对每个设备步骤预计使用的完整时间区间校验校准、维护、预约、退役及能力范围；实际开始时再校验设备在线、清洗、活动报警及联锁。
6. 设备故障或维护插入影响已排程任务时显示受影响清单，不静默移动正在执行或不可中断步骤。首期由操作员确认未执行部分的重排。

代码：`api/app/models/resource.py`、`api/app/services/station_service.py`、`api/app/repositories/resources.py`、`api/app/domain/capability.py`、`api/app/domain/scheduling.py`、`api/app/domain/preflight.py`、`web/src/features/stations/`、`web/src/features/schedule/`。验收：AC-11 至 AC-13。

### DEV-07 物料有效性与库存核算

1. 保留批号、放行、预留和盘点能力，增加稳定物料标识、基础单位、开封记录和期初余额。旧物料名称保留展示与迁移映射，不能只用名称关联不同单位的物料。
2. 有效截止时间取生产有效期和适用开封有效期中的较早者。首期实现可录入的批号开封截止时间及依据；按物料类别自动推算的具体天数待业务确认，不预置假定天数。
3. 预留、预计使用检查、下发及实际投料均校验放行、报废、有效期和开封状态。仅消耗其 BOM 所需物料的步骤需要投料许可；合法空 BOM 的方法显示“无需物料”。
4. 新增只追加库存流水，关联物料、批号、批次、步骤实例或人工业务单、来源事件、数量、单位、操作者和时间；错误记录通过受控冲正及更正记录修复，不直接修改已入账流水。
5. 首期账面库存指组织仍持有且未消耗的总量，包含已领用未消耗部分。领用与归还记录保管位置变化，不重复扣减总库存；实际消耗或损耗才扣减库存。完整多库位运营后移。
6. 每条预留维护授权预留总量、已消耗量、已核销损耗、已释放量；未耗用占用 = 授权预留总量 − 已消耗 − 已核销损耗 − 已释放。可用量 = 账面库存 − 全部未耗用占用，适用批号状态另作筛选。
7. 消耗入账同时减少账面库存和相同数量的占用；余额和流水同一事务。库存、占用均不能为负；超预留实际用量需先以明确动作追加预留并校验可用量。
8. 已领用但未消耗的数量在归还或处置确认前仍被占用。终止仅自动释放未领用、未消耗部分；已领用部分生成归还或处置待办，不能直接变回可用库存。
9. 每个库存业务事件具有稳定 ID，唯一约束至少包含组织、来源、事件 ID、明细号。设备回执、人工提交、称量和退回均覆盖；同一命令下不同部分投料可分别入账，同一事件重试只入账一次。
10. 使用明确精度的十进制数量；首期只接受物料基础单位及登记的精确换算，单位不匹配拒绝。不能用浮点误差容忍掩盖账实差额。
11. 提供批号余额、预留占用、领用与归还、消耗及差异明细；支持按批次和步骤追溯。禁止继续按步骤数量均分生成“实际消耗”。

示例：期初 100，预留 20，可用 80；实际消耗 8 后，库存 92、剩余占用 12、可用仍为 80；确认剩余 12 未领用并释放后，可用为 92；重放消耗 8 的事件，余额保持不变。

## 6 数据模型与状态契约

### 6.1 必要对象和约束

| 对象 | 最低字段/关系 | 必要约束 |
|---|---|---|
| Organization / Membership | 组织、用户、成员状态；实验室与项目稳定 ID | 组织用户关系唯一；撤销成员后新请求不得继续访问 |
| ServiceIdentity | 组织、来源标识、凭据摘要、授权资源/任务范围、状态 | 来源在组织内唯一；停用即时影响新请求 |
| Person / Qualification | 账号关联、资质范围、有效期、证据 | 执行人必须有效；历史资质变更留痕 |
| Asset / ResourceBooking | 资产、工位关联、容量、校准记录、占用时间段 | 并发预约不能超出共享资产容量 |
| Sample | 编号、来源、数量、单位、父样本、归属 | 组织内条码唯一；数量非负；不得跨组织父子关联 |
| SampleAssignment / Transfer | 样本、运行、容器孔位、条件、流转时间 | 在途孔位占用唯一；保留时间历史 |
| PlanVersion / ExperimentTask | 类型、冻结要求、负责人、执行人、批次 | 批准版本不可改；首期任务与批次一对一 |
| StepRun / WorkflowEvent | 步骤、尝试号、状态、行版本、唯一事件、处理状态 | 步骤尝试唯一；同一推进结果不创建重复下一节点 |
| InventoryEvent / Ledger | 来源事件、明细、批号、任务/步骤、数量、余额变化 | 事件明细唯一；流水只追加；非负余额及预留约束 |
| MetricDefinitionVersion | 代码、类型、单位、方法版本、规则 | 已引用版本不可原位修改 |
| AnalysisTask / IngestEvent | 样本、检测轮次、要求指标；来源、事件、摘要 | 回传事件键唯一；任务样本与组织一致 |
| ResultValue / ResultReview | 类型化值、单位、指标版本、文件、修订、质量及审核 | 相同任务/指标/结果版本唯一；审核绑定确切版本 |
| FileObject | 存储键、大小、摘要、组织、关联、状态 | 授权下载；不可删除受引用正式文件 |
| SOPVersion / ReportVersion | 版本、状态、附件、作者/批准者、发布快照 | 发布后不可变；作者与批准者不同 |
| Audit / Idempotency | 主体、组织、对象、动作、请求、版本；键与摘要 | 业务审计和写入原子；幂等作用域唯一 |

所有新增可变对象至少包含创建/更新时间和行版本。历史主键不随组织或显示名称变化。唯一约束与外键需要在正式数据库实际创建，不能只在 Python 校验。

### 6.2 状态之间的关系

| 状态维度 | 首期状态 | 谁可推进 |
|---|---|---|
| 批次执行 | 沿用现有 planned、scheduled、running、paused、fault、done、aborting、aborted 等 | 业务服务与流程推进器，依据受控事件 |
| 步骤运行 | pending、ready、running、waiting、completed、failed、unknown、cancelled | 对应设备/人工/等待/审核事件；unknown 需对账或核查 |
| 检测采集 | pending、collecting、collected、cancelled | 满足冻结指标要求的采集服务 |
| 结果质量 | unassessed、valid、suspect、invalid | 有权限的判定/复核动作，记录理由 |
| 结果审核 | pending、approved、rejected | 授权复核人，绑定结果版本 |
| 样本生命周期 | registered、received、in_use、stored、exhausted、disposed | 收样、流转、使用和处置事件；不代替检测状态 |

“批次 done”只表示运行结束；任务仍可处于待数据复核或待报告。“审核 approved”只表示审核过程完成且该版本获准使用，正式统计还需质量 valid。结果修订不反向改写已发布报告。

## 7 接口要求

### 7.1 公共契约

- 用户接口从用户认证取得组织和权限；集成接口使用服务认证。所有列表返回 `items`、`total`、`page`、`page_size`，旧接口过渡策略见第 10 节。
- 错误保留现有 `detail` 包装，增加稳定 `code`、可读 `message`、可选 `blocked`（对象、步骤、字段、原因）；401 未认证、403 无动作权限、404 对象不可见或不存在、409 状态/版本/幂等冲突、422 输入错误、423 执行门禁止动作。
- 修改及审核请求携带预期对象版本；版本过期返回 409，不能静默覆盖其他人的编辑。客户端获取最新数据后重新提交。
- 事件采集时间使用带时区的 ISO 8601；数据库按 UTC 存储，界面按实验室配置展示。日期型有效期按明确实验室时区解释，不能依赖服务器本地时区。
- 成功响应返回业务对象 ID、版本、状态与 request_id；回传重试返回原 event/result ID 和 `replayed` 标记。

### 7.3 结果回传示例

下例是新契约示例，不是现有 `ResultIngestIn` 已支持的格式。来源和组织不由请求体指定。

```json
{
  "event_id": "device-result-000123",
  "task_id": "AT-0001",
  "sample_id": "S-0001",
  "collected_at": "2026-09-21T11:00:00+08:00",
  "parser_version": "parser-1.0",
  "raw_file_id": "FILE-0001",
  "metrics": [
    {
      "metric_version_id": "METRIC-capacity-v1",
      "value": 152.3,
      "unit": "mAh/g"
    }
  ]
}
```

任务要求多个指标时，此事件可以先写入一个；全部要求指标入账后才进入 collected。这个状态不代表审核完成。任务 ID、样本 ID、指标和文件归属任一不匹配，整次拒绝。

### 7.4 库存事件示例

```json
{
  "event_id": "manual-consumption-0008",
  "event_type": "consume",
  "batch_id": "B-0001",
  "step_run_id": "SR-0002",
  "reason": "人工确认实际投料",
  "items": [
    {
      "line_no": 1,
      "lot_id": "LOT-0001",
      "reservation_id": "RES-0001",
      "quantity": "8.000",
      "unit": "g"
    }
  ]
}
```

同一业务事件重试保持 event_id 不变；同一命令下第二次合法投料用另一个事件 ID。请求头幂等键复用统一机制，库存事件唯一约束负责业务级去重；不能只凭请求头是否相同决定重复扣库。

## 8 页面交互与完成标准

| 页面 | 首期必须可完成的操作 | 关键反馈 |
|---|---|---|
| 工作台 | 我的任务、待复核、异常及过期项跳转 | 计数与列表同范围；标明下一动作 |
| 人员与资质 | 人员查询、资质登记和撤销、查看证据 | 已过期、即将到期及影响任务 |
| 仪器设备 | 资产详情、校准维护、预约、关联工位 | 不可用原因、受影响排程 |
| 试剂耗材 | 批号有效性、领用/消耗/归还、流水对账 | 库存、剩余预留、实际消耗分列 |
| 实验方案 | 类型选择、样本/指标要求、版本和审批 | 非矩阵不展示必填因子矩阵 |
| 方法与配方 | 四类节点、参数、资源和 SOP 配置 | 节点适用字段及即时校验；后端提交裁决 |
| 任务中心 | 分配、接单、转派、截止时间和关联运行 | 人员资质阻塞、待人工与待审核区别 |
| 批次详情 | 步骤执行、人工记录、事件、控制、追溯 | 未知动作显著显示，禁止一键盲目重试 |
| 样本中心 | 登记、扫码接收、分样和交接 | 当前实体位置、运行分配、历史时间线分开 |
| 数据审核 | 原始文件、采集值、质量与审核、重测关系 | 缺测不是 0；批准和质量有效分列 |
| 结果分析 | 指标/批次/版本选择、统计与导出 | 正式/探索范围、纳入和排除数量 |
| 报告与 SOP | 版本上传/生成、提交、审签、发布和下载 | 发布后只读、旧版本可查、替代关系 |

每个新增列表至少有加载、空数据、错误、无权限状态。相同操作在按钮和接口上有一致权限；按钮禁用提示不能取代后端校验。新动作成功后刷新相关余额、待办和状态，避免只刷新当前弹窗。

## 10 历史兼容、数据迁移与上线

### 10.1 历史数据规则

- 原 Sample ID 对应新物理样本，同时建立原批次的运行分配。没有实际位置记录时标记“历史位置未记录”，不能将计划工位冒充实际位置。
- 原三个固定指标转换为受版本控制的指标及结果明细；保留原 Result ID 映射、原始 URI、解析版本和模拟来源。无法取得原文件的记录标明缺失，不生成替代曲线冒充原件。
- 旧 quality 标记保留为历史质量判定，新增审核状态设为 pending，并增加 legacy_unreviewed 来源标记；正式使用前需明确复核，不能生成虚构签名。
- 旧物料库存与模拟预留存在已知不一致风险，正式切换前由责任人确认期初库存及未结预留。只按可靠证据转换实际消耗，不依据步骤比例追溯倒扣。
- 旧已锁定方案不自动视为新审批通过。历史批次继续引用原快照；使用旧方案新建正式任务前补充必要审批。旧在途批次在切换前完成或经核查迁移状态，不强行映射成已完成。
- 历史组织归属按核验结果映射。不能确认归属的数据放入受限待核对区，不能默认让所有组织可见。

### 10.2 接口与前端兼容

- 现有 `/plans`、`/recipes`、`/batches`、`/results` 等 URL 尽量保留；字段增加优先，状态语义变化必须前后端同一版本上线。
- 保留旧 `state` 的历史展示映射，新增独立审批、审核与采集状态；不能把 matrix locked 当成 approved，不能把 batch done 当成结果审核通过。
- 列表分页接口启用时，更新所有前端调用和聚合接口；如存在外部消费者，提供有明确截止日期的兼容适配，而不是让同一路径随机返回数组或分页对象。
- 原 CSV 导出保留旧字段可读映射，同时增加数据来源与审核说明。固定指标页面逐步切换到新明细，切换期间定义唯一权威写入口，不进行无约束双写。
- 结果回传与设备入口认证属于必须升级的安全契约，不保留匿名兼容入口。模拟执行器和试点适配器同步更新。

### 10.3 切换顺序

1. 固定代码和数据库基线，复制库与文件到演练环境，运行迁移及核对。
2. 在 PostgreSQL 上完成并发、隔离、库存和恢复验收；确认试点协议与实际设备。
3. 制定切换窗口：停止新任务下发，处理在途设备命令、人工待办和未结物料，再暂停写入及后台执行。
4. 完成最终数据库与文件备份、迁移和核对；独立执行迁移命令，再启动 API、后台推进器、执行器和前端。
5. 先以只读核对和指定试点任务验证；通过后开放正常创建和执行。
6. 回退时同时停止所有新写入与设备下发。对切换后已产生的物理动作和业务数据先核对，不能直接恢复旧备份丢弃真实投料或设备动作。结构可逆不等于业务动作可逆。
