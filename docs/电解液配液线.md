# 电解液配液线：C 公司 A-Lab 产线接入（模拟阶段）

C 公司 A-Lab 电解液产线在氩气手套箱里，分**物料准备段 → 配液段 → 测试段**三段，由统一上位机调度机械手、过渡舱等模组；
ILCS 编排流程、按步骤下发。当前配方是 6 固 6 液（EC 常温是固体，预热熔化后移液）。配方按 AI 预测变：量、组分、顺序都会变，
分装瓶数、每瓶分装量每次实验可配。瓶身二维码标签提前贴好，序列号来自手动导入的实验表格。NMR 这一期不做。

现在是**模拟阶段**：设备没到场，16 个工位都接内置模拟适配器，资产按校准豁免占位，原料用测试批号。
产线定义在 `scripts/lines/c-electrolyte/line.json`，`scripts/load-electrolyte-line.py` 按它登记并能跑一整批；
端到端测试 `api/tests/api/test_electrolyte_line.py` 用同一个脚本、同一组接口把整条链路跑一遍。

## 二、配液模板怎么把配方表变成流程和方案

配液线的流程骨架是固定的，会变的只有「加哪几种料、按什么顺序、每瓶多少」。所以不为每个配方手写流程，而是登记一份**配液模板**
（`FT-ELY-01`「C 公司电解液配制（6 固 6 液）」），每次拿配方表现生成。模板不走发布：它只决定怎么生成流程草稿，
生成的流程照旧走评审 → 批准 → 发布，那才是受控点。模板存在 `formulation_templates` 表（迁移 `0042_formulation_templates`，
(组织, 编号) 唯一）；改模板带 `row_version` 并留审计，不用的退役、不删除。界面上「实验设计 → 配液模板」可以直接改
（每改一处实时核对，能上传配方表按没保存的配置试算），也能复制成另一条线的模板再改；`line.json` 里的模板由登记脚本写入，
重跑 `register` 会按 `line.json` 覆盖界面上的改动。

**配方表**：第一行表头；每行一瓶。序列号列按表头认（序列号、编号、瓶号、样品编号、serial、id，不区分大小写）；其余每列一种试剂，
表头里的单位后缀 `EC (g)`、`EMC(g)`、全角 `EC（g）` 都认，没写单位按 g。每格是这一瓶这种料的质量。**0 是有意不加，空白是没填**：
同一列有的格填了、有的空着是问题（不加请填 0），整列空白 = 这次不用这种料；负数、非数字、序列号缺失或重复也都是问题，
有问题不能导入。试剂名要和物料主数据的名称对上，物料类别决定怎么加。

**一瓶一配方**：序列号对应的瓶子已登记的沿用（预览里提醒「已登记，将沿用」）；但已经在某个批次里配过液、或已处置 / 已用尽的瓶子
是问题，导入拒绝——要配新的一瓶，就用新序列号。建批次时再核一次，口径相同：方案指定的瓶子已分配给另一个没有终止的批次（含已完成的），
或在一个终止了但已经向设备发过指令的批次里（瓶里可能已经投了料），或已处置 / 已用尽，建批次拒绝，什么都不预留。
从没下发就终止的批次不占瓶子。

**生成的步骤**（参考配方生成 43 步）：

1. **物料准备段**（固定 6 步）：过渡舱载入空瓶（人工，填载入空瓶数、确认二维码完整，要签名）→ 手动分装物料（人工，确认核对并记录原料批号）
   → 手动扫码核对瓶身序列号（人工）；与此同时机械手取空瓶放到周转位；两路汇合后过渡舱转物料进配液段。之后再分两路：
   液体阶段，与过渡舱转固体物料到加料位（固体转运和加液体并行，不挡液体阶段）。
2. **液体阶段**：按表格列顺序逐个加预热溶剂与溶剂，每个溶剂加完跟一步「加料后制冷搅拌」；EC（预热溶剂）加完不搅拌；
   阶段最后一个加完也搅拌。然后 配液段拧盖 → 冷藏搅拌 → 配液段开盖。阶段第一个加料步骤只等「物料进配液段」。
   每瓶 EC 之后至少还要再加一种溶剂（类别「预热溶剂」标了 `not_last`：EC 常温是固体，单独制冷会凝固），否则导入不通过。
3. **锂盐与添加剂阶段**：同样按列顺序加（锂盐与添加剂交替，参考配方是 LiPF6 → LiFSI → LiTFSI → LiBF4 → VC → FEC → LiDFP），
   每个加完跟制冷搅拌，阶段最后一个加完不搅拌（直接关盖终混）。然后 配液段关盖 → 终混
   → 过渡舱转测试段。阶段第一个加料步骤接在液体阶段之后，同时还要等「固体物料到加料位」（两路在这里汇合）。
4. **测试段**（固定 9 步）：测试段开盖 → 电解液分装，之后分两路并行：母瓶与备用瓶关盖 → 入库；第 1 瓶电导率 → 密度黏度 → 拉曼 → 关盖 → 复测存储。

整列为 0 的试剂不生成加料步骤（预览里会提醒）。某一瓶某种料是 0，那一步照常执行，给这一瓶下发 0（上位机按「跳过这一种料」处理）。

**搅拌按瓶执行**：每个「加料后制冷搅拌」带 `applies_to`，只下发在前一步真加了料的瓶子——指令的 `params.wells` 只列这些瓶子，
没列的瓶子这一步不动；锂盐与添加剂阶段还要这瓶之后在本阶段再加一种料才搅，这瓶最后一种料加完不搅、直接关盖终混。
所以每瓶的加料与搅拌只由它自己的配方决定：不含 FEC 的 A 瓶与含 FEC 的 B 瓶同批配，A 的搅拌过程与它单独配时一样；
EMC 为 0 的瓶子 EC 之后直接接下一种溶剂，不会单独制冷。本批一瓶都不用搅的那一步不下发，记为「已跳过」并归还预约的时间窗。

**每瓶的量不在流程里**：加料步骤上只写投哪种料（`material`）和用量取哪个参数（`material_param`，这里是 `mass`），参数值写 0；
流程 BOM 留空。所以同结构（同样几种料、同样顺序）的下一张配方表**沿用同一个已发布流程**，不用重新评审。
只有设备步骤的用量能由方案给出（指令按孔位下发、设备回报后才入账）；人工步骤投的料必须列在流程 BOM 里，否则评审检查不通过。

**方案**是矩阵：每个加料步骤一个因子（水平 = 各瓶用量，带物料），外加两个实验参数的单水平因子（分装瓶数、每瓶分装量，
缺省 2 瓶、20 mL，导入时可改）。**分装量核对**（模板 `volume_check`）：每瓶总质量 ÷ 1.35 g/mL（取偏大的密度，估出的体积偏小）
估算母液体积，分装瓶数 × 每瓶分装量 + 母瓶留样 5 mL 放不下就不能导入。参考配方 72 g 约 53 mL：2 × 20 mL 可以，2 × 30 mL 不够。完全相同的配方行视为同一条件的重复瓶，每个配方的瓶数要一样。瓶身序列号按「条件顺序 × 重复号」
写进方案的指定样本，建批次时每个运行分配就指向对应的瓶子。

**建批次以后**：按本批各瓶用量之和预留物料（例如 LiBF4 只有参考瓶加 0.36 g，就只预留 0.36 g）；执行时每个加料步骤按孔位下发每瓶的量，
设备（模拟阶段是内置模拟）回报实际加了多少，消耗按回报入账，与预留按物料对账。

- 一种料的预留跨了几个批号（一个批号不够、按有效期顺序从几个批号预留）时，只写物料名的一条回报按有效期先后（与建预留时选批号同序）拆到各批号入账；
  各批号剩余预留加起来不够才拒绝并报警。
- 由方案给出用量的物料，每步的**计划量 = 这条指令实际下发的量**（各孔之和，单位取用量参数登记的单位）。中途判废的瓶子不在下发的孔位里，
  各步用量不同也各算各的，所以不会误报消耗偏差。流程 BOM 里列的物料仍按「BOM 量 ÷ 投它的步骤数」算每步计划量。

**SOP**：模板用 `sop: {"code": "SOP-ELY-01"}` 指定生成的流程按哪份 SOP 执行，固定步骤、各类别的加料步骤与搅拌步骤用
`sop_step` 写 SOP 里的步骤标题。生成时按这份 SOP **当时生效的版本**关联流程，标题换成这一版的步骤标识（`sop_step_key`），
批次页每个节点就带出对应的作业指导；SOP 没有生效版本、标题在这一版里找不到、设备能力超出 SOP 适用范围，都是导入问题。
SOP 出了新版本，旧版本关联的流程不再沿用，下次导入按新版本生成。

## 三、SOP：SOP-ELY-01 电解液配制与理化检测作业指导书

内容在 `scripts/lines/c-electrolyte/sop.json`（目的、安全与应急、17 个结构化步骤），附件 PDF 由
`api/.venv/bin/python scripts/lines/c-electrolyte/render-sop.py` 按它生成（`SOP-ELY-01-v2.pdf`，随仓库提交）。
现行 v2；已登记 v1 的环境重跑 `register` 时起草、评审并发布 v2，v2 生效后取代 v1，之后导入的配方表按 v2 生成新流程。
导入脚本登记时由研究员起草、上传附件、写结构化步骤并提交评审，QA 批准发布；要求阅读确认，执行批次的操作员（P-003）登记时即确认。
适用能力是全部 11 项 `cap.ely.*`，适用样本类型「电解液」。

步骤：过渡舱载入空瓶 → 手动分装物料 → 扫码核对瓶身序列号 → 机械手取放空瓶 → 过渡舱转运 → 溶剂与预热溶剂加注 →
加料后制冷搅拌 → 拧盖、开盖与关盖 → 冷藏搅拌 → 锂盐称量加料 → 添加剂移液加注 → 终混 → 电解液分装 → 电导率检测 →
密度黏度检测 → 拉曼检测 → 入库暂存。流程里同一类动作（三处过渡舱转运、七处开关盖、每次加料后的制冷搅拌）对应同一步。

这是**产线草案**：按产线定义与客户确认的工艺起草（温度、时间、扭力、检测次数的范围来自客户流程图），PDF 页眉注明
「现场审定前以现场规程为准」；设备程序、冷藏搅拌范围、保持与恢复方式等标了待厂商确认。现场审定后按 SOP 页面修订新版本发布，
流程下次导入自动按新版本生成。

v2 写进了按配液经验起草的工艺规则（2026-09-30），**都待客户确认**：

| 规则 | 内容 | 为什么 | 待谁确认 |
|---|---|---|---|
| 零用量组分 | 按瓶执行：某瓶某种料为 0，跳过这种料和随后的制冷搅拌 | 同一配方在哪一批里配工艺都一样，闭环训练数据才可比 | 客户 |
| EC | 预热到 45 ~ 50 ℃ 完全熔化后移液；加完不搅，紧接着加下一种溶剂；每瓶 EC 之后至少还要一种溶剂 | EC 熔点约 36 ℃，单独制冷会凝固 | 客户 |
| 配方表空白 | 0 = 不加；同一列部分空白不能导入；整列空白 = 这次不用 | 漏填不能被当成配方决定 | 客户 |
| 搅拌参数 | 加料后 -10 ℃ / 60 s / 400 rpm，带走溶解热；冷藏 5 ℃ / 600 s / 300 rpm，加锂盐前预冷；终混 25 ℃ / 3600 s / 500 rpm，完全溶解 | 取值在客户流程图的范围内 | 客户 |
| VC、FEC | 冷藏保存；使用前在手套箱内回温到 25 ~ 30 ℃、完全熔化后移液，不预冷 | 两者熔点都在 20 ℃ 上下 | 客户 |
| 分装 | 缺省 2 瓶 × 20 mL，母瓶至少留 5 mL；导入时按总质量 ÷ 1.35 g/mL 核对；分装前确认溶液澄清无颗粒 | 72 g 约 53 mL，2 × 30 mL 放不下 | 客户；每瓶量还要厂商给电导率电极的最小浸没量 |
| 手套箱 | 水、氧 ≤ 1 ppm，超限不开瓶、不加料、不分装 | LiPF6 遇水分解 | 客户；平台检查等传感器接入（见七） |
| 扭矩 | 设定值 3 ~ 30、缺省 10，数值与单位都不改 | 流程图写的 N 不是扭矩单位 | 厂商：N·cm、kgf·cm 还是夹持力 N |
| 水分 | 本期不测；原料按批号核对供应商 COA（溶剂水分一般 ≤ 20 ppm） | 不在客户确认的测试项里，线上没有卡尔费休仪 | 客户：下一期是否加 |
| 清洗 | 测试段电极、测量池每瓶之间按设备程序清洗；加料段各料走独立通道，不做瓶间清洗 | 不同配方依次接触同一检测池 | 厂商：清洗程序与残留验证 |

## 四、在界面上导入配方表

研究员登录，左侧「实验设计」→「配方导入」：

1. 选模板 `FT-ELY-01`，选配方表文件（.xlsx 或 .csv）。页面显示列识别（哪列是序列号、哪些是试剂、各归哪个阶段）、每瓶用量、
   生成的步骤列表、方案摘要，以及问题（红，必须解决）与提醒（黄）。
2. 按需要改分装瓶数、每瓶分装量与方案名称，点「生成流程与方案」。系统登记瓶子（已登记的沿用，配过液或已处置 / 已用尽的拒绝）、新建或沿用流程、新建方案草稿。
3. 之后照常走：研究员提交流程评审 → QA 批准、发布（沿用已发布流程时跳过）→ 研究员锁定并提交方案 → QA 批准方案 → 操作员建批次、
   排程、开跑检查、签名下发 → 操作员在批次页提交三个人工节点。

## 五、脚本

```bash
# 只登记主数据、SOP 与模板（能力、资产、工位、方法、物料与测试批号、指标、资质、SOP-ELY-01、配液模板）
python3 scripts/load-electrolyte-line.py register --base http://127.0.0.1:8090

# 导入配方表并跑完一批（缺省参考配方 scripts/lines/c-electrolyte/formula-20260929.csv）
python3 scripts/load-electrolyte-line.py run --base http://127.0.0.1:8090 [--table 配方表.xlsx] [--bottles 3 --volume 15]
```

- 只走 HTTP，与界面调同一组接口；签名用演示账号口令逐次签署。分工：`engineer` 登记能力、资产、工位与起草方法，`qa` 发布方法、
  放行批号、批准流程与方案，`operator` 登记物料批号、重连适配器、建批次与执行，`researcher` 登记指标与模板、导入与提交，
  `admin` 授予资质。
- 幂等：已有的能力、工位、方法（按名称 + 能力找已发布的）、物料、批号、指标、资质、模板先查后用；`line.json` 里的模板改了，
  重跑会按它更新模板。资产只给新登记的工位建 `AS-<工位>` 占位；已登记的工位沿用它现在关联的资产（换成实物资产、删掉占位后重跑
  不会再建回来）。已登记的工位若内置模拟没打开示意检测值，会补上。新登记的工位登记后重连一次（新适配器先离线），重连前执行器报的「适配器失联」条件恢复后由脚本确认并关闭；别的工位、条件仍在的报警不动。
- `run` 不能对同一张表重复跑：一瓶一配方，第一批跑过以后这些序列号都配过液，再导入会被拒。再跑一批要用新序列号的配方表。
- `run` 需要执行器在跑（本机部署的 executor），执行门关着会直接停。批次完成后打印每步检查点（工位、投料量、检测值、数据标记）、
  消耗入账与预留对账、批次报警；然后 QA 逐条复核设备写入的检测结果，研究员出报告、QA 批准并发布——跑完后「数据审核」
  「结果分析」「报告管理」里都有这一批的数据。
- 正式环境（`ILCS_ENVIRONMENT=production`）拒绝运行。

## 六、模拟阶段的占位项

| 占位 | 现在 | 为什么 |
|---|---|---|
| 设备 | 16 个工位都是内置模拟适配器，适配器配置 `simulate_outputs: true` | 设备未到场。内置模拟按下发参数回报投料量（每瓶之和），检测步骤按方法输出规则生成确定性的示意值（上下限之间 35%–65% 处），不是物理模型 |
| 资产与校准 | 资产型号按设计填，`calibration_applicable=false`，豁免理由「模拟阶段占位：设备未到场，接真机前按实物登记型号、序列号与校准」 | 不登记资产开跑检查会挡；没有校准记录又不豁免，排程会挡 |
| 原料批号 | `LOT-SIM-<名称>-01`：溶剂 1000 g、锂盐与添加剂 500 g，有效期 2027-12-31，储存条件注明「模拟阶段测试批号」，QA 以「复验合格」放行 | 预留与消耗对账要有已放行批号 |
| 能力的恢复策略 | 按物理常识预填（加料、分装不可重试，搅拌可暂停续跑……），每项 `note` 标「待厂商确认」 | 保持时限、能否续跑 / 重试要厂商给 |
| 风险评估 | 模板 `risk` 写「RA-ELY-01（模拟阶段）」 | 开跑检查要求流程有风险评估编号 |
| 检测结果 | 电导率、密度黏度两个检测方法的输出项关联了指标（`ely_conductivity`、`ely_density`、`ely_viscosity`）：设备回报后系统按瓶写成检测结果（每瓶一张「设备回报」检测任务），进「数据审核」；内置模拟给的值带「模拟示意值」标记。导入脚本 `run` 跑完批次后由 QA 逐条复核、再出报告并发布 | 示意值能走通审核与报告，但不是实测：闭环训练数据把带「模拟示意值」标记的结果排除；接真机后同一条链写的就是设备实测值 |

## 七、接真机前要替换的东西

1. **驱动**：每个工位改成真实适配器（按[设备适配器配置模板](设备适配器配置模板.md)选驱动或套设备接入模板），关掉 `simulate_outputs`，
   过接入验收。上位机的物料映射接口定了以后，由驱动把 `delivered.materials`（物料名、单位、实际量）按真实称量回报；
   步骤上的 `material` / `material_param` 已经随指令交给驱动。
2. **资产**：按实物登记型号、序列号、固件，取消校准豁免并录入校准证书；型号变了要同步改设备方法的适用型号。
3. **能力**：恢复策略按厂商确认的保持时限、可否暂停 / 重试改掉「待厂商确认」；工位能力极限按设备手册核对。
4. **设备方法**：程序号（`ARM-PICK-EMPTY`、`DOSE-SOLVENT`……）换成上位机实际的程序标识，计划时长按实测改；改方法要修订并重新发布。
5. **原料**：测试批号作废，按实物入库、复验放行；物料名称要与配方表表头、批号一致（按名称精确对账）。
6. **风险评估与 SOP**：模板 `risk` 换成正式的风险评估编号；SOP-ELY-01 经现场审定后修订发布正式版本（附件换成受控文件）。
7. **人员资质**：除 P-003 外，实际上岗的操作员也要有全部 `cap.ely.*` 资质。
8. **上位机按瓶执行**：加料指令里某瓶是 0 = 这瓶跳过这种料；「加料后制冷搅拌」指令只处理 `params.wells` 列出的瓶子，
   没列出的瓶子这一步不动（每孔写着这一步的温度、时间、转速）。
9. **手套箱水氧**：传感器读数由服务身份经 `POST /api/runtime/environment` 上报（区域写手套箱名，指标 `h2o_ppm`、`o2_ppm`）之后，
   在模板的加料、开盖、分装步骤上加 `"environment": [{"metric": "h2o_ppm", "max": 1, "zone": "配液段手套箱"},
   {"metric": "o2_ppm", "max": 1, "zone": "配液段手套箱"}]`（测试段同理），开跑检查与每步投递前都会核对。没有读数、读数超过
   30 min 没更新都会挡住投递，所以模拟阶段不加。
10. **厂商待定**：扭矩的物理单位（定了按厂商单位改能力参数登记）；电导率电极的最小浸没量（定每瓶分装量）；检测池瓶间清洗程序与残留验证方法。
