# 实验室管理与数据智能平台：基于 ILCS 的修订方案

版本：v4（2026-09-21）
依据：《实验室管理&数据智能平台 技术参数》2.1、2.2 节；本地 ILCS 代码（`ilcs/api`、`ilcs/web`、`ilcs/executor`）；四轮评审意见
定位：总体设计基线，兼作开发验收依据。v4 相对 v3 的变更见第 14 节
核验范围：以下"已有"均指本地代码实现，尚未核验线上部署版本与真实设备接入情况

---

## 1. 总体结论

**以现有 ILCS 的配方、排程、批次执行与追溯能力为基础，向前补齐资源与实验准备，向后补齐样本、数据审核与报告管理。** 优先把一次实验从准备到归档完整贯通，再扩展 AI 优化、AGV 协同等能力。

四轮评审收敛后的共识：

1. 现有执行能力可复用，最大的缺口是它们尚未与完整的实验室管理业务连接。
2. 已确认十三条现有问题（2.2）。其中五条阻碍新需求成立；另有两条影响现有数据正确性：消耗不扣减库存导致可用量回升（P5），执行完成自动授予质量结论（P4）。
3. 结构性开发前需要先完成技术前置：版本化迁移、数据库切换规划、文件存储接口、幂等与回传认证。
4. 样本、步骤与流程推进、结果与回传事件、组织归属、物料消耗与库存五个核心模型要先定，否则后续模块会重复建设。
5. 第一阶段范围要收敛到"一类代表性实验可贯通"，并以两条并行工作线推进。
6. 定稿前三项硬性补齐：库存一致性、质量状态分列、流程持久化推进。每项对应到实施阶段和验收用例。

## 3. 核心概念与术语

### 3.1 实验业务对象

| 概念 | 含义 | 与现有对象的关系 |
|---|---|---|
| 实验方案 | 研究什么、如何设计条件、测哪些指标、如何判断结果 | 现有"实验计划"扩展为通用方案，矩阵实验是其中一种类型 |
| SOP | 操作依据、注意事项和必须遵守的规范 | 新增；版本关联到方法和执行记录 |
| 实验方法 / 配方 | 具体步骤、参数、物料需求和所需能力 | 现有"配方"，界面改称"方法与配方"，保留全部能力 |
| 实验任务 | 谁在什么时间完成哪些工作，可含人工与自动化步骤 | 新增任务中心 |
| 执行批次 | 一次具体运行，保留实际使用的方案、方法、SOP 版本 | 现有"批次"，继续作为自动化执行主入口 |

### 3.2 样本对象（三分法）

| 对象 | 记录内容 |
|---|---|
| 样本 | 唯一编号、条码、来源、类型、母样关系、数量、保存条件、状态、附件 |
| 运行样本分配 | 某次运行中的样本、容器 / 托盘、孔位、条件组、重复编号、所在工位 |
| 样本流转记录 | 从哪里到哪里、交接人、时间、数量、确认方式 |

支持两条路径："先有样本再安排检测"（外部送样、生产抽样）和"实验过程中产生样本"（自动化批量实验）。记录母样、子样及重测关系。

历史数据处理：现有样品转换为"样本 + 运行分配"，保留原编号和结果关联。旧系统未记录的实际交接、历史位置和分样过程不能靠迁移补造，迁移方案需明确哪些历史信息完整、哪些只保留现有记录。

### 3.3 归属与范围

| 概念 | 含义 | 首期处理 |
|---|---|---|
| 组织 | 数据归属与隔离边界 | 硬隔离，核心对象必带 |
| 实验室 | 资源所属、实际操作地点 | 以稳定标识关联人员、设备、库位，用于筛选和统计 |
| 项目 | 协作与业务访问范围 | 以稳定标识关联方案、任务，不用自由文本标签承载；权限配置界面后移，首期场景要求的项目隔离首期落实 |

### 3.4 术语统一

- "样本 / 样品"、"请检 / 请验"选定统一叫法，全系统一致。
- 样本来源同时支持：研发方案、生产抽样、外部委托、手动登记。

## 4. 核心模型调整

### 4.1 结果与指标

不做任意键值对，也不立即删除旧结果表。新增：

- **指标定义**：编号、名称、数据类型、单位、允许范围、检测方法版本、适用样本类型。
- **回传事件**：来源（由认证确定）、事件编号、内容摘要、接收时间、关联检测任务。负责去重，唯一约束落在这一层。
- **结果明细**：样本、检测任务、回传事件、指标、数值、单位、采集时间、质量状态、审核状态、版本。

约定：

- 一个回传事件可关联多条指标结果明细，整次回传原子入账。
- 检测任务完成的定义是"该任务要求的全部指标均已入账"。允许分批回传时，收到一个指标不能把整个任务标为完成。
- 执行状态、检测完成状态、质量标记、审核状态四者分别维护。任何执行完成路径（回传入口、批次完成、恢复）都不自动授予质量结论。
- 过渡期规则：现有统计与黄金批次对比依赖样品的质量字段。在结果明细上线前，未审核数据在统计中标注"待审核"，正式报告默认排除；上线后统计改读结果明细的审核状态。

原三个电池指标作为首批指标定义迁入，现有分析页面逐步适配。

### 4.2 步骤类型与流程运行层

| 步骤类型 | 完成条件 |
|---|---|
| 设备步骤 | 下发指令，等待设备回执（现有路径） |
| 人工步骤 | 生成待办，等待记录提交及必要签名 |
| 等待步骤 | 等待时间或业务条件满足 |
| 审核步骤 | 等待批准、驳回或退回处理 |

流程运行层决定下一步；设备执行器只负责设备动作。首期只支持顺序执行，条件分支、并行、子流程后移。

持久化推进规则：

- **短事务**：每次状态转换是一个独立的短事务。不跨人工等待或设备运行持有事务。
- **持久化等待与事件**：等待状态（等待谁、到期时间、触发条件）和触发事件（设备回执、人工提交、审核结论、定时到期）都落库。
- **后台推进器**：由明确的后台运行机制轮询到期等待与未处理事件并推进，可由现有执行器的轮询模式推广而来。没有用户请求时，等待节点由推进器唤醒；设备回执作为事件触发下一步。
- **一致性**：状态转换与后续待办 / 指令的创建在同一事务提交。
- **重复事件保护**：事件带唯一标识，已处理的事件重放不产生第二条后续指令或待办。复用现有指令幂等与检查点机制。
- **重启恢复**：进程重启后从持久化的等待与事件表找回未完成推进。设备状态可通过检查点确认的，按现有恢复规则继续；设备动作结果无法确认的，进入"结果未知，待人工核查"状态，禁止盲目重发。数据库事务不能保证外部设备动作不重复，这一情况必须单独处理。

影响范围：配方步骤类型（`domain/recipe_rules.py` 及前端镜像 `web/src/features/recipes/rules.ts`）；批次服务与执行服务（`services/batch_service.py`、`services/execution_service.py`）；恢复规则（`domain/recovery.py`）；新增的运行状态与事件模型；执行器循环。`domain/lifecycle.py` 只负责删除与停用判据，仅需为新增对象补充判据。

### 4.3 设备资产与执行工位

- 工位继续描述"能做什么、参数范围是多少"。
- 新增资产档案描述"设备是谁、归谁管理、维护和校准是否有效"：资产编号、序列号、责任人、位置、验收、维护工单、校准记录与证书、报废流程。
- 一台资产可对应零个或多个工位。普通检测仪器、手工操作台纳入资产管理，不必具备远程控制能力。
- 设备预约、维护窗口、自动排程共用同一资源日历。

### 4.4 组织归属与访问控制

- 样本、方案、任务、批次、报告、附件等核心对象带组织归属；确属同一组织的历史记录按核验结果回填。
- 组织上下文来自认证令牌，不信任前端传入的组织编号。
- 统一改造仓储访问入口：按编号查看、修改、导出、附件下载、统计全部经过范围校验；防止跨组织绑定样本、任务和报告。
- 后台进程不使用绕过组织过滤的万能权限：后台任务携带其处理对象的归属；设备凭据限定可操作的资源与检测任务范围；确需跨组织的调度只开放必要的资源占用信息，并明确授权范围。审计区分"用户操作"与"系统操作"。
- 首期保留静态角色权限；人员资质作为独立的数据驱动校验。权限组配置界面后移；首期场景要求的项目隔离首期落实（与 3.3 一致）。

### 4.5 物料消耗与库存一致性

针对 P5：

- 新增**库存流水**：入库、领用、消耗、退回、损耗、盘点调整，每条带来源（称量、设备回执、人工确认）、数量、单位、时间、操作者或系统上下文。
- 可用量 = 账面库存 − 未消耗预留。消耗入账时同时扣减账面库存并关闭预留中对应的数量，两者在同一事务。
- 批次终止或取消只释放未耗用数量；已消耗部分留在流水中。
- 部分投料可对账：预留量、已交付量、实际消耗量、退回量四者可核对。
- 重复回执不重复扣库：复用命令级幂等与检查点去重，不在库存层另做一套重复判断。
- 完整的采购、供应商、库房库位运营后移到第二阶段；消耗入账与库存一致性列入第一阶段 B。

## 7. 技术前置

### 7.1 数据结构迁移

- 建立版本化迁移（Alembic），含历史数据转换、核对和回退方案。
- Alembic 批处理模式可在 SQLite 上重建表完成结构变更，因此"必须先换数据库才能改表"不成立。
- 切换 PostgreSQL 的真正理由是并发写入：api 多副本与执行器独立进程同时写库，SQLite 单写者会成为瓶颈。面向正式多人使用与设备并发写入，按 PostgreSQL 规划，并在第一阶段 B 进入多人使用前完成切换。

### 7.2 文件存储

- 定义统一的附件存储接口：上传、下载、权限、校验、备份。
- 依据部署条件选择受控文件目录或对象存储，不要求一开始部署独立存储服务。

### 7.3 部署环境约束

- 线上为内网 HTTP，非安全上下文。浏览器摄像头扫码、剪贴板等 API 不可用。
- 键盘输入模式的扫码枪（有线、无线、蓝牙）可先支持；如需手机或平板摄像头扫码，必须先解决 HTTPS。

### 7.4 幂等与回传认证

现有幂等缺陷（P8）影响全部写接口，作为共用改进处理：

- 幂等键绑定调用者；同键不同内容拒绝并提示冲突。
- 幂等记录与业务写入在同一事务提交。
- 回传去重以业务键为准：来源 + 检测任务 + 事件编号落在回传事件记录的唯一约束上（见 4.1），请求头幂等键作为可选优化。即使调用方不传幂等键也不产生重复结果。
- 事件编号必填，重试时保持不变；未携带事件编号的回传拒绝，或走明确写出的兼容规则。
- 校验来源是否有权提交该检测任务，以及该任务是否属于该样本与组织。
- 统一事务边界（幂等记录与业务写入同事务）涉及多个服务的提交点，作为范围明确的小设计包处理，不按零散修补排期。

回传认证：

- 接口认证与来源授权，每个适配器或集成系统持有独立凭据。
- 来源标识由认证信息确定，不接受调用方自填设备名称。
- 记录原始文件、采集时间、解析版本、事件编号。
- 重试去重与重测留档明确区分：合法重测或结果修订使用新的检测记录或版本，保留原记录。

## 12. 验收用例（起点）

### 12.1 资源约束

- 资质过期的人员不能被分配对应任务，不能执行对应设备操作。
- 校准失效的设备不能进入相应工步；排程时对预计使用时段内失效的设备不作为候选。
- 过期、超开封期限或质量状态不合格的物料不能预留、下发、投料。
- 维护窗口内的设备不被排程占用。

物料与库存：

- 消耗入账后账面库存正确减少，可用量不回升。
- 同一步骤的重复回执不重复扣库。
- 批次终止只释放未耗用数量，已消耗部分保留在流水中。
- 部分投料时预留、交付、消耗、退回四个数量可对账。

### 12.2 样本与数据

- 分样后子样可追溯母样；重测记录独立保留，原记录不被覆盖。
- 采集完成的数据未经审核不能进入正式报告。
- 批次已完成、结果未审核时，结果仍保持待审核，不因批次结束被标为有效，不能进入正式报告。
- 报告绑定确定的数据版本；数据修订后原报告不变，新报告引用新版本。
- 跨组织的样本、任务、报告不能互相绑定；按编号直接访问其他组织对象被拒。

### 12.3 回传去重

| 情况 | 预期行为 |
|---|---|
| 同一来源、同一回传事件、相同内容重试 | 返回原结果，不新增结果行 |
| 同一事件编号、不同内容 | 拒绝并提示冲突 |
| 两个相同请求并发到达 | 数据库最终只保存一份业务结果 |
| 合法重测或结果修订 | 使用新的检测记录或版本，保留原记录 |
| 无认证或来源未授权的回传 | 拒绝，审计记录来源地址 |
| 来源有认证但无权提交该检测任务，或任务不属于该样本与组织 | 拒绝并审计 |
| 未携带事件编号 | 拒绝，或按明确写出的兼容规则处理 |
| 一次回传包含多个指标 | 整次原子入账，全部成功或全部不入账 |
| 一个检测任务分多次回传 | 每次只入账对应指标；全部要求指标入账后任务才完成 |

### 12.4 执行

- 加急重排不改变已执行记录和不可中断步骤。
- 人工步骤未提交记录时流程不进入下一步；提交后进入设备步骤并能正常下发。
- 等待步骤到期后由后台推进器唤醒，无用户请求也能推进。
- 同一触发事件重放不生成第二条后续指令或待办。
- 重启恢复分三种情况验收：
  - 设备状态和检查点可确认：按恢复规则继续，不重复设备动作。
  - 设备动作结果无法确认：进入"结果未知，待人工核查"状态，系统不自动重发。
  - 设备已动作、结果尚未落库时进程退出：重启后不重复动作，该步骤进入人工核查。
