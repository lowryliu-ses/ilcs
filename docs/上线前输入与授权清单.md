# ILCS 上线前输入与授权清单

这份清单只收集代码无法自行决定的现场事实和授权。未勾选的项目不得由开发人员猜测，尤其
不能把演示账号、模拟设备、示例库存或空白 SOP 当作正式数据。

## 1. 变更授权与窗口

- [ ] 目标主机、SSH 用户及访问路径已确认：`[主机 / VPN / 跳板机]`
- [ ] 已明确授权在目标机上传制品、构建镜像、执行迁移和切换 8090 服务
- [ ] 变更窗口：`[开始时间]` 至 `[结束时间]`
- [ ] 业务停写负责人：`[姓名 / 联系方式]`
- [ ] 放行负责人：`[姓名 / 联系方式]`
- [ ] 回退决定人：`[姓名 / 联系方式]`
- [ ] 80/443 公共网关不由本次变更直接修改；如需新增路由，已有网关责任人单独批准

## 2. 数据路径（二选一）

### A. 全新正式库

- [ ] 确认没有需要保留的历史业务数据
- [ ] 只运行 `seed --force --master-only`
- [ ] 已填写真实组织 ID、代码、名称、IANA 时区
- [ ] 临时管理员口令通过受控渠道交给指定接收人，首次登录立即改密
- [ ] 改密后从 `.env` 删除 `ILCS_INITIAL_PASSWORD`

### B. 沿用现有 PostgreSQL 库升级

- [ ] 已确认现有库即为唯一业务库，并记录当前迁移版本（`migrate.py status`）
- [ ] 切换窗口内停止 API、执行器及所有外部写入
- [ ] 已用 `pg_dump -Fc` 取得备份并核对可读，附件目录同一窗口备份
- [ ] 升级后运行 `migrate.py verify`，核对组织归属、库存流水、在途批次、未知指令
- [ ] **不得再运行演示 seed 或 `--master-only` 覆盖现有数据**

选择：`[A 全新正式库 / B 沿用现有 PostgreSQL 库升级]`

## 3. 正式配置事实

- [ ] `POSTGRES_DB / USER / PASSWORD` 已生成并存入受控密码库
- [ ] JWT 密钥、口令 pepper、数据库密码互不相同
- [ ] 正式入口 URL 与 `ILCS_CORS_ORIGINS` 一致：`[https://...]`
- [ ] 组织：`[ID] / [代码] / [名称] / [时区]`
- [ ] 设备网关白名单：`[主机或 IP 列表]`，不使用 `*`
- [ ] `/opt/ilcs/data` 属主为 `10001:10001`、权限 `0770`
- [ ] `/opt/ilcs/secrets` 属主为 `10001:10001`、权限 `0700`
- [ ] 单个设备凭据文件属主为 `10001:10001`、权限 `0400`
- [ ] 正式 `.env` 不进入代码同步、备份报告或工单正文
- [ ] 已运行 `check-production-readiness.py --initial-seed` 且没有错误

## 4. TLS、网络与时间

- [ ] 上游网关提供 HTTPS；8090 只在受控内网开放
- [ ] 浏览器到网关、网关到 ILCS、ILCS 到 PostgreSQL 的允许路径已确认
- [ ] API/执行器只能访问列入白名单的设备网关
- [ ] PostgreSQL 不暴露到前端网络或非管理网段
- [ ] 主机、数据库、设备网关、仪器时间同步到同一可信 NTP，时区记录一致
- [ ] 防火墙、DNS 和证书到期责任人已明确

## 5. 真实设备试点（每台设备一份）

先填写 [设备适配器配置模板](设备适配器配置模板.md)，至少提供：

- [ ] 厂商、型号、序列号、固件版本、现场工位 ID
- [ ] 官方协议/SDK、接口样例、错误码表、超时建议
- [ ] 查询、去重、保持、恢复、终止能力的真实语义
- [ ] 参数单位、精度、上下限及设备侧校验规则
- [ ] 命令 ID 是否持久化，断线重连后是否可查询
- [ ] TLS 证书链、认证方式和凭据交付渠道
- [ ] 安全联锁、急停、物理副作用和人工恢复步骤
- [ ] 供应商/设备负责人和可用联调窗口
- [ ] 已将 `ILCS_EXECUTOR_SIMULATE_HEARTBEAT=0`（正式环境设为 1 会被硬门禁拒绝启动）
- [ ] 本批次涉及的每个工位都已配置 `kind=real` 的真实驱动（正式环境下模拟工位的批次无法下发）
- [ ] 完成断联、重复回执、超时、重启对账和真实物理副作用验收

## 6. 备份、恢复与回退

- [ ] 备份目录位于独立存储：`[路径 / 存储系统]`
- [ ] 数据库和附件使用同一停写窗口生成，均有 SHA-256 清单
- [ ] 备份保留周期、访问权限和异地副本责任人已确认
- [ ] 已在隔离数据库运行 `backup-and-recovery-drill.sh` 并保存报告
- [ ] 回退前停止所有新写入与设备下发
- [ ] 已核对切换后产生的数据、投料和设备动作，不会用旧备份静默覆盖真实记录
- [ ] 旧静态原型容器只停止不删除，回退命令和责任人已确认
